= MIDI Playback and ANSI Music Rendering Design
:toc: left
:toclevels: 3
:sectnums:

Design and research date: 2026-11-06.

Status: implemented. This document records the approved contract and the
resulting implementation; it supersedes the earlier open research choices.

== Approved implementation contract

* Deliver MIDI files and ANSI-to-MIDI together. The sole new application
  preference is a global library enable mask, `MidiModes`, analogous to PCM
  output. Enable compiled methods by default. Use MIDI automatically for ANSI
  when available, and retain classic tones as its fallback.
* Routing and MIDI-file instruments use the platform/library configuration:
  ALSA_OUTPUT_PORTS (including comma-separated routes), Windows MIDI_MAPPER,
  Apple's built-in DLS synth, FluidSynth user configuration then its default
  bank, and finally libADLMIDI's embedded bank. No destination, renderer,
  instrument, SoundFont or GM-capability preferences are added. CoreMIDI
  destination selection is outside this implementation. ANSI captures select
  GM Lead 2 (sawtooth), bank 0/program 81 (zero-based), on MIDI channel zero.
  FluidSynth ANSI playback uses a dry voice: channel-zero chorus/reverb
  sends, including preset sends, are suppressed while ANSI plays. Saved
  effect controllers are restored before file playback; global effect
  configuration and other channels are unaffected.
* Queue cached files with `APC SyncTERM:A;QueueMIDI;<filename> ST`; query usable
  playback with `APC SyncTERM:Q;midi ST`, replying `CSI = 7 ; 102 ; available n`.
  Support SMF formats 0/1 and RIFF/RMID, normal channel messages, SysEx,
  tempo/running status and SMPTE timing. Reject unsupported format 2 cleanly.
* Files and ANSI strings share channel 0's FIFO. Channel 0 flush, fades,
  volume, wait, busy and completion notifications always address the music
  player, including external output. Forward embedded SysEx normally.
* Both ANSI renderers use seven complete C-through-B octaves: O0..O6 and
  N0..N83. N0 = O0 C = MIDI 36 (about 65.406 Hz); N83 = O6 B = MIDI 119
  (about 7902.133 Hz). Resolve accidentals before checking the final range;
  invalid resolved notes are rests. Preserve capture and timing conventions.
* Internal synthesis follows PCM consumption; external events use monotonic
  deadlines. Bound the FIFO to 128 requests, parser/message storage to 64 MiB,
  and PCM render-ahead to 4096 frames. Reject new work without disturbing
  accepted playback. Cancel notes/events and join owned workers on teardown.
* Third-party CMake choices are AUTO, RUNTIME, STATIC and OFF independently
  for ALSA, FluidSynth and libADLMIDI. AUTO selects runtime loading when
  available; explicit choices require their complete compile/link contract.
  STATIC means actual archives with their dependency closure, not import
  libraries or an accidentally selected shared object. Windows/macOS APIs
  use normal system linkage. Keep all CMake state target-scoped and C17.
* Add a MIDI category to Build Options listing the five methods, compiled
  support and runtime/static/system linkage. Retain the three-column
  Menu.buildOptions contract; reading it never probes libraries or devices.
* PCM and MIDI masks are independent. Quiet suppresses both. Headless
  fixtures disable both, while libretro permits only internal PCM renderers.
* Verify independent expected notes/events, malformed input and bounds,
  channel controls and cancellation, runtime/static/mixed/disabled builds,
  private-Xvfb CP437/UTF-8 behavior, and Windows cross-builds without Wine.
  Commit complete verified changes without pushing.

== Implementation

`src/media/music` owns the ANSI interpreter, checked SMF/RMID iterator,
message decoder, adapters and per-terminal worker. CTerm supplies a borrowed
audio runtime and owns the player through reset/disconnect/destruction. The
application runtime holds the independent MIDI mask and shutdown state; no
new process-wide player or permanent native worker is introduced.

The player mutex protects the FIFO, cancellation generation, completion
sequence and controls. Backend synthesis and message delivery belong to its
single worker. A zero-length flush drops pending requests, advances the
generation, clears PCM and waits for the old active request to acknowledge
cancellation. A faded flush drops pending work and fades the active request;
newly accepted work survives in the next piece. Destruction wakes and joins
the worker before releasing the backend, stream, queue and synchronization.

Internal output is 44100 Hz signed-16 stereo through the existing mixer.
Software MIDI renderers establish a fixed source gain on initialization by
rendering the actual ANSI synth voice (GM Lead 2 sawtooth, program 81, A440,
velocity and CC7 100, centered pan) into discarded buffers. The middle second
of a two-second reference is matched by K-weighted level to the existing
beep/ANSI waveform at A440. ITU-R BS.1770 K-weighting accounts for frequency
content and rejects DC separately in each channel. Its two filter stages are
used only to measure the references, never to equalize playback. The silence
floor still uses unweighted AC power. This chooses an internal default
relative to existing beep/PCM levels; no additional gain setting is exposed.
Probe release/effects buffers are discarded until quiet, with an eight-second
bound, and the ANSI synth voice is restored. References at or below four
PCM units RMS retain unity source gain; calibration is bounded to +/-48 dB.
Partial banks remain usable. FluidSynth calibration uses its library-default
gain and then restores the configured live gain, so user gain changes still
have their intended effect.

This source gain accompanies MIDI PCM buffers into the mixer's wide
accumulator, where it combines with the unchanged channel gain before final
soft clipping. Do not multiply/clip the signed-16 source before that stage.
The source gain is constant throughout playback, preserving relative note
velocities, controllers and instrument levels; it is not per-file or
per-block normalization. Classic PCM generation, channel defaults, explicit
volume and fade controls retain their existing levels. Native MIDI outputs
cannot be measured through the PCM renderer and do not use this calibration.

Rendering uses at most 1024 frames per call and observes the 4096-frame
outstanding window. Per-request PCM completion markers include backend
latency, allowing consecutive captures to render without an intervening drain
while waiters retain their acceptance snapshot. Native output uses absolute monotonic event deadlines
with bounded, cancellation-aware waits. Queueing retains an opened cache
file rather than reopening an arbitrary pathname. Validation walks the entire
file before acceptance, using small blocks instead of constructing unused
SysEx copies. Playback revalidates the open file before sending events.

The active SMF parser reserves half the 64 MiB arena for payload and track
state; the message decoder reserves the other half for split SysEx assembly.
It merges format-1 tracks by tick and source-track order, retaining only the
next event per track. Tempo arithmetic preserves fractional nanoseconds;
SMPTE -29 means 30000/1001 frames per second. Format 2 is unsupported.
Files release sustain/notes at their end and retain a two-second release tail
in logical busy/wait state. ANSI uses its existing articulation without an
additional per-capture tail.

Both renderers share the checked ANSI parser and its integer-millisecond
rounding. Classic notes use equal temperament at A=440 Hz. MIDI uses melodic
channel zero and note numbers 36..119. File playback may use all sixteen
channels, percussion, pitch bend, pressure, controllers and SysEx. Returning
to ANSI restores its default channel state and explicitly selects GM Lead 2
(sawtooth), bank 0/program 81, before any ANSI Note On. MIDI files reset to
their ordinary default programs and retain their own Program Changes. No
instrument-coverage discovery rejects partial banks.

External stream volume uses native stereo gain when available; otherwise it
combines the logical left/right gains with each MIDI channel's volume/pan.
The fallback is quantized to MIDI controller resolution. Repeated identical
gain updates do not continually resend controllers. File controllers remain
beneath this overlay, and Reset All Controllers preserves volume/pan.

`MidiModes` under `[SyncTERM]` accepts `ALSA`, `FluidSynth`, `libADLMIDI`,
`WinMM`, `AppleDLS`, and numeric bits separated by `|` or `,`. Missing settings
mean all bits enabled; zero disables MIDI without disabling PCM. Program
Settings edits only these enable bits. Backend selection occurs when idle;
an accepted active piece retains its backend until it completes or is flushed.
Libretro excludes external ALSA/WinMM destinations and uses internal PCM only.

== CMake linkage

[cols="1,3",options="header"]
|===
| Option | Values
| `ST_MIDI_ALSA`, `ST_MIDI_FLUIDSYNTH`, `ST_MIDI_ADLMIDI`
| `AUTO` (default), `RUNTIME`, `STATIC`, `OFF`
| `ST_MIDI_WINMM`, `ST_MIDI_APPLE`
| `AUTO` (default), `ON`, `OFF`
|===

AUTO requires usable public development headers and compiles a lazy runtime
adapter. RUNTIME requires that header/API contract explicitly. STATIC requires
a real archive, its complete transitive link closure and a successful API link
probe. Prefer upstream static imported targets; pkg-config static metadata
supplies private dependencies for archive discovery. Shared/import libraries
cannot stand in for a requested archive. Static synthesizers carry the runtime detected by their C++ toolchain in
their link closure, including for C-only executable/shared-library consumers.
SyncTERM component sources remain C17. Windows SDK and
Apple framework APIs use ordinary system linkage. No whole-application static
flag is used; the libretro/shared application boundary remains supported.

For example, `-DST_MIDI_ALSA=OFF -DST_MIDI_FLUIDSYNTH=RUNTIME
-DST_MIDI_ADLMIDI=STATIC` mixes runtime loading and an archive. Use
`CMAKE_PREFIX_PATH` for dependencies installed in a separate prefix. The
`ST_MIDI_<name>_INCLUDE_DIR` and `ST_MIDI_<name>_ARCHIVE` cache entries may
identify a nonstandard development installation. Explicit missing requirements
are configuration errors. Runtime libraries may be absent at application
startup without making them hard executable dependencies.

Build Options always includes five MIDI rows. A compiled row names runtime,
static or system linkage; an omitted method is unchecked. The native/Wren
catalog contract remains `[category, displayName, enabled]`, without device
or runtime-library probing. Wren settings expose `Settings.midiModes` and
`Menu.midiModes`; there is no new Wren MIDI playback API.

== Verification boundaries

`music_parse`, `music_decode`, `music_calibrate` and `music_player` use literal
file/message/note expectations, a recording MIDI destination, and pull-only
PCM. They exercise
queue ordering and continuous PCM across capture boundaries, request limits,
malformed files, split SysEx, SMPTE timing,
volume/fades, generation cancellation and shutdown without opening devices.
Calibration tests use independent libebur128 reference levels at 440 Hz,
1 kHz and 4 kHz, with controlled sine references, separate per-channel DC
offsets, DC-only silence, bounded noise gain, transport/render
errors, state restoration and external-output exclusion. Player captures
verify calibrated source gain, unchanged channel defaults, explicit volume,
wide mixing before clipping, faded cancellation and subsequent playback.
Literal bank/program messages and file-to-ANSI-to-file transitions verify
that ANSI selects its synth voice and files retain their own instruments.
`st_midi_synth_test fluid|adl|apple` is a manually selected internal-synthesis
smoke test; it verifies nonzero PCM and never creates a physical audio output.
Add `--levels` to inspect actual ANSI synth and classic waveform playback
through the player and pull-only mixer at A440. It reports source gain, final
PCM AC RMS, channel means, raw peaks and the level difference. Attack/release
and per-channel DC are excluded from RMS; actual PCM samples are unchanged.
The independent final-output measurement uses Welford central moments rather
than calibration's sum-of-squares calculation. The pre-mix classic A440
reference is approximately 9095.19 AC RMS, with a mean of -14276.70 PCM units.
Including that DC produces total RMS 16927.69 and an erroneous 5.4 dB boost.
AC RMS is a power diagnostic, not proof of equal perceived loudness.
The test never opens a physical audio device. An optional output prefix,
`--levels /tmp/midi-check`, writes `-midi.s16` and `-classic.s16` captures:
signed 16-bit little-endian stereo at 44100 Hz. These are final mixer output,
suitable for an independent meter such as FFmpeg's `ebur128` filter.

Independent final-output measurements at library-default gain give -20.6
LUFS for classic and -20.5 LUFS for both FluidSynth 2.6.2/FluidR3 GM and
libADLMIDI 1.6.1/bank 0 at A440. A representative normal-articulation ANSI
phrase measured -20.3 LUFS for classic and -19.8 LUFS through FluidSynth,
compared with -18.9 LUFS before frequency weighting. A frontend-clocked
capture of the real 100 ms `audio_beep()` path was byte-identical to the
matching classic PCM capture. The beep and PCM effect gains are unchanged.

The filter is a sustained-reference calibration using the frequency weighting
specified by https://www.itu.int/rec/R-REC-BS.1770/en[ITU-R BS.1770]. It is not
a gated programme meter or per-file normalization. The independent filter
references were measured with libebur128 1.2.6; the implementation adds no
runtime dependency on that library. Renderer modulation can vary sustained
level between notes; the source calibration remains fixed during playback.
`--envelope` compares the 10..100 ms onset AC RMS with the 0.5..1.5 second
sustain AC RMS at MIDI notes 36, 48, 60, 69, 81, 96, 108 and 119. An onset
more than 2 dB above sustain fails this manually selected renderer check.
The previous square preset failed it at note 36 (+3.38 dB); the dry sawtooth
voice stays below +0.5 dB in the tested FluidR3 GM and ADLMIDI banks.
`--effects` checks file/ANSI/file reverb tails and repeated ANSI preparation
with an enabled-reverb fixture. It verifies dry ANSI output and restoration
of the file's effects; renderers without an ANSI effect override skip it.
Native MIDI device/auditory verification is separate from these tests.
`music_build_modes` builds mock public-ABI archives and a C++ private
dependency, then checks AUTO/RUNTIME/STATIC/mixed/OFF selection, C-only
module linking, absent headers/archives, rejected shared-library substitution
and a missing transitive dependency. These mocks test build policy, not
third-party ABI or musical correctness.

CTerm tests cover cache authority, channel-zero controls, parser reset and
split input in CP437/UTF-8. Application control captures verify unavailable
feature replies, rejected requests and parsing recovery. Settings tests cover
mask persistence and independent PCM policy, and the settings/Build Options
UI is checked at 80x25 and 72x24. Graphical tests use private Xvfb only.

Platform coverage and actual build configurations are recorded with the
implementation's verification results; cross-compilation does not claim
native device playback. Windows tests are never run under Wine.

Implementation verification on FreeBSD uses Clang 19 and GCC, focused
ASan/UBSan checks, real libADLMIDI 1.6.1 and FluidSynth 2.6.2 archives, and
runtime FluidSynth PCM synthesis. Windows checks cross-compile both 32-bit
and 64-bit MinGW application DLLs and launchers; they are not native execution.
macOS DLS and physical MIDI destinations still require native verification.
