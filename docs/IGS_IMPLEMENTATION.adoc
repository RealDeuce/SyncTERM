= IGS 2.21 implementation goal
:toc:

== Goal and current state

Implement complete IGS 2.21 serial graphics support using SyncTERM's existing
palette-indexed bitmap framebuffer, indexed off-screen images, image-format
conversion at boundaries and existing local timing facilities. Complete all
47 top-level commands and all 16 X selectors as a new graphics mode, one fully
implemented, independently tested and committed step at a time. Target
intended IGS221/IG221.ACC serial behavior and US TOS 1.04 software graphics.
There is no additional persistent planar framebuffer or foreign clock model.
The primary reference is ~/IGS/docs/igs/; chapters 01, 02, 109, 159, 201,
202, 206, 208 and 210 establish provenance, scope and interpretation.
The user's port policy below takes precedence over historical fidelity gates.

The executable coverage ledger is link:../src/tests/igs/conformance.json[conformance.json].
No command is implemented yet. Parser-only tests do not establish command,
rendering, sound or application support. The X dispatcher remains pending
until all extended selectors and their dispatch behavior have passed.
Experimental CTerm IGS input routing is available for native integration
tests; application profile/menu selection and command handlers remain pending.

conversion, timing and fidelity requirements are part of the goal itself;
they do not depend on conversation-specific overrides.

== Agreed implementation boundary

* Exact indexed pixels, palettes, glyphs, console output and overlays for
  intended, valid IGS operations in all three Atari ST resolutions.
* Implement GIST effects, PSG notes, console sounds and MIDI with a good-faith
  aim of sounding correct. Reuse SyncTERM MIDI. No bit-identical PCM or
  development waveform/perceptual comparison gate. Supply a manual listening
  checklist after implementation, without claiming listening was performed.
* Honor explicit waits, playback durations, input deadlines and cancellation;
  do not emulate old hardware throughput or foreign clocks. Convert protocol
  time units to the local monotonic/audio domain where needed: initially
  60 sync-wait units per second and 200 note/envelope units per second.
* Correct clear original bugs. Do not reproduce memory corruption, accidental
  overflow, uninitialized scratch or machine-fault behavior. Preserve defined
  valid-input quirks unless identified as bugs; record deliberate corrections
  and recovery rules with tests.
* Low 320x200/16, medium 640x200/4, monochrome 640x400/2. Preset low resolution
  and Atari ST encoding on selection; retain explicitly selected ST modes.
* Only 2.21 serial compatibility is required. Nested script behavior is in
  scope; standalone Atari applications, file viewers and host deliveries are
  not. Add historical compatibility only for an identified existing consumer.
* BIG and CONDOR inform reuse boundaries, not additional mode implementations.

== Architecture

Create an internal graphics-protocol library with its own target-based CMake
component. Separate framing, argument acquisition, typed operand evaluation
and execution. Command descriptors share parameter/coordinate descriptions
where behavior agrees. Keep variable-arity readers, exact input ownership,
raw payloads, suspended operations, bounded replay and cancellation explicit.
Commands consume protocol bytes before any text decoding. Shared machinery
must allow BIG's I# framing and CONDOR's load/execute framing without putting
Atari raster or sound policy in the parser. Do not migrate RIP or SkyPix.

IGS and RIP are add-on parsers at the same pre-ANSI insertion point in the
CTerm receive path. Dispatch the selected graphics parser at the existing
st_cterm_write stage, before base ANSI/VT52 emulation; forward ordinary bytes
through the existing write_plain path. Graphics framing, arguments and raw
payloads belong to the selected add-on parser before the base parser sees
them. Do not place IGS inside the ANSI parser or feed one protocol's payloads
through the other protocol's parser. Sharing this insertion point does not
require migrating RIP into the new IGS-family grammar. Preserve existing
wire-encoding, hook, capture and intentional semantic-input bypass contracts.

IGS owns per-terminal parser/interpreter state, two indexed memory images,
logical/physical routing, palette and drawing attributes, text, console and
overlays. SyncTERM's existing bitmap framebuffer is the authoritative screen.
Reuse existing Atari ST/VT52 facilities where verified. All scene mutations
use the same authoritative pixels and existing bitmap-console presentation.

Parsing and graphics run on the terminal owner. Long work is resumable and
bounded per pump. Use existing local monotonic deadlines; inject local time
for tests rather than adding an IGS clock subsystem.
Audio uses existing mixer ownership; any required raw MIDI queue uses the
existing music worker and decoder. Reset/disconnect cancel pending work and
release all owned audio, buffers and overlays.

Append ST_GRAPHICS_IGS_221, ST_CTERM_GRAPHICS_IGS_221 and GraphicsMode.igs221
as value 5. Menu/config label: IGS (2.21). Preserve existing values. Replace
enum-order checks that currently classify later graphics values as SkyPix.
Update profiles, menus, Wren, session creation, input, geometry and docs.
Check status, resize, scrollback, reset and reconnect isolation.

== Framebuffer and image conversion decision

Use the existing SyncTERM framebuffer and indexed pixel buffers for both
screen rendering and off-screen images. Do not add a persistent planar
framebuffer or planar shadow of the screen. The existing pixel representation
already retains palette indices and resolves them to RGB at presentation;
exact pixels and palette animation do not require planar rendering.

Convert native image data at format boundaries. Decode an X11 upload into
indexed storage when it is imported. Encode only at a boundary that requires
native bytes, or repack/reinterpret when an image's plane layout changes.
Ordinary drawing and G blits operate directly on physical colour indices;
they must not pack/unpack planar data on every transfer. Remove any console
palette-bank offset before Boolean raster operations and restore it afterward.
X14 changes routing, not image representation, and needs no conversion itself.

Preserve the complete decoded memory-image capacity, including padding and
retained contents, rather than keeping only a cropped screenshot. Track the
current plane layout and descriptor/row-stride metadata explicitly. A row
stride change can be a view of the same decoded storage. A plane-count change
must preserve the intended native-byte reinterpretation at the format-change
boundary, without introducing a second persistent authoritative copy.

G's sixteen Boolean operations are equivalent on the active physical index
bits. Native bitmap codecs may be small boundary helpers; native word loops,
bus behavior and a second screen are not prerequisites for valid-input pixel
accuracy. Screen-to-screen, screen-to-memory, memory-to-screen and
memory-to-memory transfers all use indexed working data.

Use the existing console's text rasterization, scrolling coordinates, damage,
snapshots and overlay ownership. Its current public read API allocates/copies
both pixel phases and its blitter implements replacement. If those interfaces
make indexed raster operations expensive, add only the narrow bulk operation
needed to avoid repeated full-screen copies, retaining locking and damage
handling. Do not use that API limitation as a reason for a planar screen.

This decision supersedes the original plan's authoritative planar screen and
the subsequent suggestion to retain planar off-screen buffers. The experimental
planar-surface code has been removed. st_igs_image instead stores indexed pixels
and converts native data only at format boundaries. Do not add a planar renderer.

== Timing conversion decision

IGS timing values are units to translate into SyncTERM's local time domain,
not a requirement to emulate foreign clocks. Use the existing monotonic time
and deadline facilities for pauses, receive timeouts and cancellation. Convert
sync-wait counts at 60 units/second initially, seconds to ordinary host
durations, and 200 Hz note/envelope units to 5 ms or corresponding local audio
sample positions. Keep sync-wait conversion policy localized so PAL or native
vsync can be selected later without changing command parsing or drawing.

Do not introduce a separate IGS clock origin, free-running video/sound tick
counters, Atari interrupt delivery or CPU-cycle scheduling. A bounded wait
uses a local deadline and resumes through the existing owner/poll path. Note
and effect updates use local audio sample timing or scheduled elapsed-time
updates as needed; do not infer elapsed protocol time from callback count or
buffer chunk size. Oscillator/envelope phase is synthesis state, not an
emulated Atari system clock. Idle IGS sessions need no foreign clock ticking.

Preserve intended duration/count behavior and continued sound during waits,
with cancellation on reset/disconnect. Original clock-wrap and timeout bucket
accidents remain outside the compatibility target. Inject local monotonic
timestamps or sample positions for deterministic boundary/error tests.

The separate st_igs_clock experiment has been removed. Use existing local
timing facilities and narrow unit conversions when implementing commands.

== Completed steps

The internal st_graphics_protocol C17 library implements configurable attention,
explicit buffered entry, command descriptors, fixed/dynamic parameter acquisition,
typed operands, bounded text/raw fields and suspension/cancel/EOF boundaries.
Native graphics_protocol_parser tests pass, including every focused split,
bytewise replay, literal reader examples, opaque binary markers, unknown
commands, limits and recovery. Tests do not establish IGS command execution.
Parser port corrections are recorded in IGS_CONFORMANCE.md.

The command ledger's 47+16 entries and listed chapters were independently

=== Indexed native-image conversion

st_igs_image owns indexed st_pixel_buffer storage for an entire 32000-byte
native memory image, including padding and retained contents. Import/export
accept arbitrary byte ranges at format boundaries. Plane-layout changes
preserve native-byte meaning using temporary conversion storage and replace
the indexed buffer only on success. No persistent planar copy is retained.
Changing a G row-stride view does not invoke conversion.

Native igs_image tests use independent literal byte/index vectors from
chapters 03/05/159. They cover all three plane layouts, partial imports across
group/section boundaries, retained full capacity, invalid indices/bounds,
failure retention and plane changes. Round-trip/partition checks supplement
the literal results. These are format/storage tests, not G or X11 completion.

Configured with cmake -S . -B build and built st_igs_image_test using the
existing native FreeBSD /usr/bin/cc Release configuration. CTest igs_image,
st_pixels and graphics_protocol_parser all passed. The superseded planar
surface and separate clock experiments and their tests have been removed.
Commit: 3fe002a.

=== CTerm pre-ANSI IGS input integration

CTerm selects IGS alongside RIP in st_cterm_write, before its existing base
input/VT52 path. An experimental ST_CTERM_GRAPHICS_IGS_221 value 5 requires
Atari ST VT52, pixel capability and native ST geometry. SkyPix checks in CTerm
now name its two modes explicitly. Profile/menu selection remains pending.

cterm_igs_input verifies ordinary text and VT52 controls through the real
CTerm path in all three ST geometries, Atari ST byte/UTF-8 input and status
on/off, with every focused input split and bytewise replay. Graphics-owned
header bytes resembling VT52/UTF-8 input are consumed before base decoding.
Semantic replacement input still bypasses graphics. Parser lifecycle checks
cover reset, reset from an input hook, incomplete-header timeout, disconnect,
destruction and invalid emulation/geometry. Existing bitmap contents survive
the first ordinary byte. No command descriptors are registered in this step;
these tests do not establish IGS command or payload execution.

Partial header acquisition uses a five-second local monotonic deadline after
input progress. Tests inject local milliseconds; there are no foreign clock
domains. Reset discards partial grammar and defers parser mutation until an
active callback returns. Explicit source EOF discards incomplete commands
without fabricating arguments and flushes held ordinary prefix text.

Configured/built the native Release SyncTERM CMake project. All 24 CTerm
tests passed, including RIP/SkyPix, and the term RIP encoding/key/wire and
application graphics-scrollback checks passed. Completion commit is recorded
by the next completed step. All 47 command and 16 selector entries remain
