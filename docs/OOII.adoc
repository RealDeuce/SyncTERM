= SyncTERM Operation Overkill II terminal manual
:toc:

== Selection and placement

Operation Overkill II (OOII, also written Operation Overkill ][) is an
embedded ANSI-art/menu expansion protocol. It runs at the connected-session
wire boundary and passes ordinary bytes to the configured terminal. It is
not another raster graphics mode. Expanded resources always render as
ANSI/CP437 independently of the ordinary connection encoding.

Mode zero leaves OOII command interpretation disabled and watches for the
original maintenance-complete banners. One banner ends in the question
`Do you have the Overkill Ansiterm installed? (y/N)`; the other contains
`HX Force retinal scan in progress ...`. Detection compares their complete
original bytes, including color controls, backspaces and padding, across
receive-buffer boundaries. Merely sending the visible text is insufficient.
The banner itself is passed through before following commands are enabled.

Modes 1–3 select the retained artwork generations. Local mode selection
clamps to this range (or zero/off) and discards incomplete frames and
partial banner matches. Negotiation below can change the active generation.

== Frame and argument grammar

A frame begins with raw byte `AB` hex and ends with `7C` hex (ASCII pipe).
Inside it, commands are case sensitive and can follow one another. Parameter
blocks use underscore separators; numeric blocks are decimal strings. No
Unicode encoding of the opening byte is used: UTF-8 for U+00AB is not the
OOII introducer.

The frame buffer is 256 bytes including its trailing NUL storage. At most
255 wire bytes, including introducer and closing pipe, execute as one frame.
A NUL or excessive length discards the frame through its closing pipe.
An incomplete frame is not executed. Mode changes also clear unfinished
collection. Fields and resource-table indices are bounded in the native port.

There is no escaping for a pipe inside a field. The block reader optionally
skips an initial underscore, reads through the next underscore or frame end,
and leaves later command parsing to the caller. Empty/nonnumeric numeric
fields follow the decimal conversion's zero result. Artwork contains its
own terminal movement and attributes rather than pixels addressed by the
wire command.

== Frame command reference

[cols="2,5",options="header"]
|===
|Command |Action
|A–E |Full complex artwork: main, barracks, headquarters, communications, wastelands, respectively.
|F–K |Base artwork: main menu, barracks, storage, tech center, control room, radio room.
|0 |Choose one of ten embedded logon pictures for the active generation.
|1 |Print the embedded games-room bar narrative.
|2–9 |Recognized text-dispatch range without an additional implemented narrative.
|a–v |Expand the small menus below, consuming their command-specific blocks.
|w–z |Recognized small-menu dispatch range without an implemented menu body.
|! |Build the recruit-status display, reading its initial attribute block.
|# |Scanner/map subprotocol, described below.
|$ |Play an embedded sound selected by the following byte.
|? |Negotiate artwork generation and send the compact reply below.
|Backslash |Disable OOII after the current frame.
|===

Uppercase L–Z enter the artwork dispatcher but select no embedded picture;
the dispatcher still performs its clear/home prefix. Unknown commands are
consumed without inventing a payload length.

== Scanner and status

`#` reads a subcommand. F draws the full scanner frame; T draws its text
panel. M reads location/style bytes and nine numeric map blocks, then renders
the nine cells using the original tile/color tables. O supplies object/detail
updates, D supplies descriptive scanner content, and P positions the scanner
output. These are native game-field formats, not ANSI escape arguments.
The retained tile mappings include walls, terrain, recruits, objects and
unknown cells in CP437. Rendering is clipped/handled by the ANSI terminal
and cannot overwrite SyncTERM's separately owned status bar.

The `!` status command first clears/homes and reads a decimal attribute.
It draws the fixed recruit, location, training, squadron, strength, dexterity,
hit-point, radiation, accuracy, bravery, crystals, disease, kills, experience,
level, hunger, weapon, armor, outfit and equipment field layout. Later game
output supplies its values. Embedded lookup tables are bounded; an invalid
item index does not read unrelated memory.

audio does not reinterpret the remaining frame or change its terminator.

== Negotiation, examples and lifecycle

`?` reads a numeric block, normalizes it to 1 or 2, sets local mode to
that value plus one, and replies with raw `AF`, ASCII selected value, pipe.
There is no CR, LF or NUL. An absent/old-version number selects 1.

For example, frame bytes `AB 3F 32 7C` request generation 2, select local
mode 3, and reply `AF 32 7C`. `AB 24 31 7C` selects the welcome sample;
`AB 41 7C` clears/homes and expands the main complex artwork. These examples
require OOII already enabled by detection or local selection.

Ordinary connection bytes outside frames retain their encoding and receive
path. Expanded ANSI uses CP437 without recursively executing newly expanded
OOII frames. A mode change while rendering is honored after stable resource
selection. Disconnect/destruction discards incomplete state. OOII does not
add a generic terminal identity, graphics coordinate query or mouse report.
