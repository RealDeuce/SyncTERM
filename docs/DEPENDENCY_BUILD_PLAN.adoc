= Dependency Build Implementation Checklist

This records the approved dependency/linkage/reporting implementation and its
verification. Implementation and native platform validation are tracked
separately; cross-compilation is not native execution. Legacy Synchronet
sources are reference material only.

== Required behavior

* Separate feature enablement, dependency linkage (AUTO/STATIC/SHARED/RUNTIME)
  and source (AUTO/INSTALLED/BUNDLED), with explicit selections enforced.
* Default to native backends and static third-party libraries on macOS and
  Windows. Keep existing shared/runtime defaults elsewhere. Explicit mixed
  linkage and pinned source builds work on all applicable platforms.
* Resolve each shared dependency once. SyncTERM crypto, TLS and DeuceSSH use
  exactly the same provider installation/target.
* Prefer suitable installed archives, including Homebrew, before pinned
  builds. Match headers, ABI, architectures, deployment targets and required
  transitive dependencies. System libraries/frameworks link normally.
* Download hash-verified pinned sources when needed, with offline/cache/local
  archive controls. Keep all generated work in the build tree.
* Preserve v1 libsndfile formats/codecs (FLAC, Ogg/Vorbis, Opus, MP3 with
  mpg123/LAME), and JPEG XL decoder/CMS/thread functionality.
* Retain all existing external backends, including curses implementation/ABI
  distinctions, terminfo, X11 extensions, Wayland/xkbcommon, PCM and MIDI.
* Report every Build Options item, plus requested/resolved options, linkage,
  source/version/path, architecture and automatic-disable reasons. Save the
  report for CI. Runtime-loaded support does not promise runtime availability.

== Verification scope

Local checks run on FreeBSD. The Clang Debug application uses the normal
runtime media backends and one installed shared OpenSSL provider for crypto,
TLS and DeuceSSH. GCC application, Wren host/settings and audio-file checks
also passed. Directly linked console tests run under private Xvfb; native
Wayland execution is skipped because no test compositor is available.

Pinned static libsndfile with all six codec prerequisites passes independent
FLAC, Vorbis, Opus and MP3 decode/format checks. Pinned static JPEG XL with
Brotli, Highway and LCMS2 passes image checks. Pinned OpenSSL and Botan crypto
checks, Botan TLS checks, static/shared/runtime MIDI selection fixtures, and
the pinned FluidSynth/ADLMIDI music fixtures pass. The pinned PipeWire client
loads its matching modules and starts/stops its loop without opening a server
connection or physical audio device. No auditory or native-device coverage is
claimed; the pinned FluidSynth bank/render path still needs a configured
SoundFont.

The dependency fixtures exercise installed/static/shared/runtime choices,
invalid selections, reconfiguration, concurrent cold downloads, offline cache
and local archives, corrupt hashes, and adding/removing compiler definitions
without losing prerequisite headers. They also check Unicode archive names
under a C locale, Windows search-path separators and Botan's make fallback.
Follow-up fixtures cover identical-size/timestamp installation changes,
configuration-specific generated-header ordering, normalized prerequisite
names, versioned shared-library aliases and rejection of a static archive for
SHARED, plus Windows archive response files and object-path budgets.
Native-SDK selection fixtures use
host-built libraries to check policy; they do not emulate a macOS ABI.

Native Linux execution, including mixed linkage, passed in pipeline 12907.
The macOS job passed in pipeline 12909. Further dependency-lifecycle corrections
for Linux, Windows and OpenBSD need another native CI run; universal macOS
builds also remain unverified.
No Windows target is executed under Wine.
Not every pinned recipe or possible linkage combination has native execution
coverage. The configuration report and dependency paths are retained with CI
artifacts so those results can be assessed against the actual configuration.

The complete MinGW64 application cross-links with the pinned static audio and
image decoder stack. Import inspection finds OS and compiler-runtime DLLs, with
no decoder DLL dependency. Pinned Botan's crypto test executable also
cross-links separately. These Windows binaries are not executed locally.
The follow-up MinGW checks also build the pinned Botan SHA-256 subset in a
directory containing spaces, using the patched archive response rule, and
compile/install pinned mpg123 with bounded object paths. Their archives are
inspected locally; no Windows execution is claimed.

The final native selection covers 22 checks. Twenty pass in the original CTest
run; MIDI build modes and Wren settings initially hit their normal execution
limits under the reported system load. The identical configured commands and
assertions pass on rerun (119 seconds and 3 seconds) with a larger local
allowance. The final six-check Botan integration run uses execution deadlines disabled.
The repository's normal test limits are unchanged.

The full application also builds against the pinned static Botan provider.
Its configuration inventory, crypto, encrypted-list, TLS, SSH and bulk SSH
checks all pass. Crypto, TLS and DeuceSSH consume that same provider target.
