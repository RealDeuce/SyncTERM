= BIG 1.03 implementation goal
:toc:

== Goal and current state

Implement complete, fully enabled BIG 1.03 terminal graphics in SyncTERM,
using ~/IGS/docs/big/ as the authoritative reference. The BIG 1.03 executable
is 248206 bytes,
SHA256 `edc9e2280d822d41361a11f622d8a70e16ada4e792a4944a77cc26af532f4a1c`;
the bundled manual labels itself 1.02. BF 1.02 is a distinct excluded target.
The implementation
inventory has 36 top-level commands including X dispatch and nine X selectors:
45 entries. BF file-viewer behavior, the original DOS client UI, demo
restrictions and CONDOR implementation are excluded. The reference's 64
accepted research requirements are not 45 completed SyncTERM commands.

The unlimited goal is active. CGA 80x25 and the shared numeric-reader
boundary are complete; ordinary BIG numeric acquisition, the shared RNG
core, stored numeric evaluation and source/deadline parser callbacks are
implemented.
BIG mode6 is selectable with native I0/I1/R indexed-console effects, g and X6,
wire & setup, source/footer replay and local stored-loop keys. Drawing commands, sound and full
command acceptance remain pending (0/45). The implementation ledger is
link:../src/tests/big/conformance.json[conformance.json].

== Standalone implementation contract

Complete each command as an independently tested, verified and committed
step. Read its full original caller, downstream, state, input, flow, reply,
failure and lifetime contracts before implementing it. Do not infer behavior
from an IGS command with the same letter, accepted syntax or a registered
callback. Establish X dispatch early; finish the parent entry only after
X0..X8 are implemented and accepted.

=== First step: CGA 80x25

Add normal PC CGA 80x25 (INI `CGA80x25`): 80x25 cells, 8x8 font bank, 640x200
raster, 4:3 display aspect, existing PC palette/blink, default attribute 07 and
cursor scanlines 6..7. Preserve ordinary PC font selection and existing
80x25 behavior. The original IBM 5160 BIOS sets cursor mode 0607; this mode
does not require emulating the CGA device or changing existing font data.

Append ST_SCREEN_MODE_CGA_80X25 as stable ID 32 and expose
ScreenMode.cga80x25. Existing mode IDs remain unchanged. Present CGA
immediately before EGA in startup/settings/session/BBS and canvas choices.
Keep Menu.screenModes as an ID-indexed name catalog; add ordered
Menu.screenModeChoices [value, label] rows. Canvas choices retain actual
mode values, independent of row position. Verify persistence and native
geometry as well as menu presentation.

=== Graphics mode, storage and timing

Add BIG(1.03) as graphics mode 6 and GraphicsMode.big103. Default to
VGA-capable behavior, CP437, 640x350 and the supplied IBM VGA console-font/
palette profile. R1 is 640x200/80x25/8x8; R2 is 640x350/80x25/8x14;
R3 is 640x480/80x30/8x16. BGI graphical text has separate font metrics.
Resolution changes use existing window-size preservation behavior.

Use the existing indexed bitmap framebuffer and indexed off-screen pages/
images. Preserve capacity, padding, stride and separate active/visual/memory
page ownership. Convert native image formats at import/export/layout
boundaries, not each blit. Add no persistent planar framebuffer. Follow BIG's
interpreter-local page/image variables and retained application state rather
than importing IGS's different lifetimes.

Translate protocol waits and music scheduling into existing local monotonic
deadlines or audio sample timing. Add no foreign system-clock domains, BIOS
interrupt execution or hardware throughput delays. Sound oscillator/envelope
state advances through local sample timing. Muted operation must still make
logical progress.

Preserve normal BIG byte consumption, WORD results, pixels, palettes, fonts,
state, replies and ordinary quirks. Use bounded resources and checked host
arithmetic; document safe corrections to memory corruption, uninitialized
state and unsafe failures. Defined protocol WORD reductions use explicit
arithmetic rather than host undefined behavior.

=== Original numeric rounding

Retain the original chapter 34 software/default 64-bit-significand result.
In particular g3 at resolution 3 maps Y 5 to 11, not 12. The exact finite
adapter is g2: `truncate_toward_zero(7*n/4)`; g3: zero when `n == 0`,
otherwise `sign(n)*floor((12*abs(n)-1)/5)`, followed by the defined low 16-bit result.
Use a wide magnitude for -32768. This preserves original numeric results
without an x87 implementation or a foreign floating environment.

BIG owns its four-slot destructive WORD reduction, continuation and special
byte consumption, substitution and timeout policy. Do not reuse IGS's
four-digit rejection, CR/LF skip, uppercase R or array-lookup grammar. Supplied
loop values bypass wire acquisition and scaling. Dynamic arity must not
repeat numeric side effects or random draws.

=== Shared parser and BGI reuse

BIG I# and chaining enter the same pre-ANSI insertion point as IGS and RIP.
Ordinary bytes continue to base emulation; payloads remain opaque. Extend
the reusable graphics parser with an optional incremental numeric-reader
interface reporting explicit consumption, completion and suspension. Keep
BIG arithmetic, deadlines and source policy outside the generic grammar.
Preserve IGS behavior and separate RIP/SkyPix grammars.

Revalidate chapter 83's reuse findings against current source. Extract narrow
shared BGI kernels and matching tables actually used by RIP and BIG. Retain
BIG-specific clipping adapters, stroke schedules, flood/curve algorithms,
state, pages and image semantics where whole native entries differ. Use
original BIG bitmap/font data and four V100 CHR assets, not newer RIP fonts.
Retain imported provenance and notices. Do not rewrite a whole raster
library or import unused APIs to obtain a matching lower kernel.

=== Keyboard and mouse pointer: accepted hybrid behavior

Retain BIG's keyboard pointer control and original X6 keyboard step rates.
Also let native mouse motion position the software pointer directly in BIG
viewport pixels. The most recently delivered keyboard/mouse movement wins;
keyboard movement never warps the OS pointer. Stationary mouse/button
observations must not undo a keyboard movement. Track the last mouse sample
separately from the software pointer; changed valid coordinates on a button
event also account for coalesced motion.

A valid left press arms selection; left-button release invokes the same
click/confirm action at the current software pointer position. Preserve
keyboard confirm/cancel behavior and emit at most one selection. UI-handled,
disabled, status/outside presses must not arm a later click; wheel-up remains
local scrollback. Reset, EOF and cancellation clear armed/pending selection
so a later release cannot affect another acquisition. Use existing session
event ownership and pointer save-under cleanup. Keep BIG's pointer shapes,
zones, hit testing and deferred replies distinct from IGS's wire semantics.

X6 controls keyboard steps and never quantizes direct mouse coordinates.

=== Sound

Implement PC-speaker effects/notes and AdLib register-stream playback through
the existing audio mixer and local sample timing. Use a bounded C17
YM3812-only adaptation of the pinned BSD ymfm algorithms, retaining notices
and only the required OPL2 functionality. BIG N is AdLib playback, not MIDI
translation. Test synthesis, state, muted progression, cancellation, reset and
teardown. Bit-identical reference PCM and manual listening are not gates;
provide a manual audio checklist when implementation is complete.

acquisition. Final-r work precedes command completion even after loop mode

application loop/RNG state. Rendering I/R defaults must not reinitialize it.

(91/5) directly into local monotonic nanoseconds. Numeric timeout is the first
integral ns beyond 73 nominal units: 4010989011ns. Every byte or auxiliary
acquisition starts a fresh deadline after its effects. A late ready byte is
consumed before its timeout substitution; BEL occurs before construction and
scaling. Loop delay converts the current signed duration on each poll from
the same local start. Zero/negative delay still samples/probes; available keys
shorten delay without being consumed there. Only checkpoint bytes03/18 cancel.
A pending key read retries without another peek.

=== Common footer, flow and repeated-body execution

`st_big_control.c` implements the original21/32/33/43 control owners and
resumable counted output. A footer repeats only for exact loop1 plus a reader
call; repetition precedes finishing XON, type/gang reset and deferred output.
Exact did_loop1 clears before the XON helper. Other/inherited loop words do
not imply that helper. Type becomes SPACE and the gang marker X after loop/
flow completion. Chaining preserves pending input; a nonchain exit clears
pending BEFORE its first output and clears only its local command on return.
Normal BIG return does not unconditionally clear the shared loop WORD.

Flow samples its mode gate once and reloads signed repetition count and byte
for each admitted request. Deferred input reloads signed WORD(count+1), with
wrap, before each data iteration; count7fff emits no data. It reads current
payload only after readiness, increments after accepted output, and checks
the current append-CR byte after the data loop. CR has no additional readiness
probe. NUL, ff, pipe and tilde remain literal bytes. A yielded send holds its
already acquired byte; a yielded readiness check does not retest the admitted
