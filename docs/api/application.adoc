[[api-application]]
== Wren and application assembly

This layer composes the project libraries into persistent menu/picker state,
per-connection scripting state, startup policy, and the executable.  The C
host boundary is documented here; Wren-visible classes and methods are
authoritatively documented in link:Wren.adoc[Wren.adoc].

=== Wren VM

Target `st_wren_vm` is the vendored Wren interpreter with its meta and random
optional modules.  Its public embedding header is
link:../src/scripting/wren_vm/include/wren.h[wren.h], and its upstream layout/license note
is link:../src/scripting/wren_vm/README.md[src/scripting/wren_vm/README.md].  SyncTERM keeps the vendor
implementation private and disables computed-goto extensions so it remains a
portable C17 target.  The `st_wren_vm_link` test verifies the embedding link
surface.

Do not add SyncTERM policy directly to the VM.  New product bindings belong in
`st_wren_host`, where their ownership, VM availability, and safe-mode behavior
can be tested independently of the interpreter.

=== SyncTERM Wren host

Target `st_wren_host`; C header:
link:../src/scripting/wren_host/st_wren_host.h[st_wren_host.h].

`st_wren_host_t` owns the persistent menu VM and isolated picker support.  Its
configuration borrows the display, menu console, optional picker console,
application paths, session history, audio runtime, and application-lifetime
hyperlink registry.  Those objects must outlive the host.  The host is not a
general concurrent VM service; its caller serializes host/VM operations.

`st_wren_host_run_menu()` runs until the menu exits or selects a profile.  The
destination profile must already be initialized and is replaced only when
`has_selection` is true.  URL selection builds the same temporary profile as
the Wren quick-connect path.  Screen-mode and last-error queries are borrowed
observations of host state.

`st_wren_host_begin_session_mode(host, selected)` saves the menu's current
mode and actual geometry, then applies the profile's mode (`CURRENT` leaves
it unchanged). It rejects nesting. Pair every successful begin with
`st_wren_host_end_session_mode(host)` after connection dialogs, disconnect
notices, and session destruction, including connection failures and application
exit. End clears the session surface and reinstalls the saved menu mode on
both menu and picker consoles, including fonts, palette, and configured cursor.
This restores menu-selected, custom, and externally resized modes rather than
assuming the startup mode. Both calls return zero on success or an `IO_ERROR`;
a failed begin attempts restoration, and end without an active scope is a no-op.

Each `st_wren_connected_t` is a fresh connected-session VM associated with one
profile and logical console.  It borrows its host, console, profile, and
optional SFTP provider for its lifetime.  Pumping dispatches queued host work;
interpret adds source to that VM; shell closure delivers the matching lifecycle
event.  Destroy the connected context before any borrowed object.

The provider-neutral SFTP interface is asynchronous:

* `submit` must copy every request pointer before returning and issue an ID
  unique among unpolled requests.
* `poll` returns one response, no response, or an error.  Every pointer in a
  response is borrowed until the next `poll` call or provider destruction.
* `cancel_all` is the shutdown boundary.  The provider context remains owned
  by the connection layer.

On the Wren side, async results resume captured fibers; Wren is cooperative and
single-threaded, not an `async`/`await` runtime.  Menu, picker, and connected
VMs have different available bindings and lifetimes.  Module resolution checks
the root user script directory, then the active event directory, then embedded
modules.  Follow link:WREN_GUIDANCE.md[WREN_GUIDANCE.md] before editing
scripts or bindings.

Tests include `wren_host`, the `wren_*` script suites, directory and picker
tests, and the loader audit cases registered by `src/scripting/wren_host/CMakeLists.txt`.

=== Startup policy

Target `st_app_startup` exposes three small policy headers:

[cols="2m,5"]
|===
| Header | Contract

| link:../src/st_command_line.h[st_command_line.h]
| Parses borrowed `argv` storage into an action, path/script/URL choices,
backend and presentation policy, connection defaults, geometry, and safe-mode
flags.  `invalid_argument` identifies rejected borrowed input.

| link:../src/st_console_startup.h[st_console_startup.h]
| Merges settings and command-line policy into separate logical-console and
physical-display configurations plus initial fullscreen state.

| link:../src/st_app_state.h[st_app_state.h]
| Decides whether a clean normal exit may persist runtime scaling, accounting
for safe mode and the startup/current screen modes.
|===

Tests: `app_startup` and `command_line_empty_backend`.

`src/st_terminfo.h` is the narrow executable helper which writes SyncTERM's
terminfo source to a caller-owned stream.  It is exercised by
`syncterm_terminfo` rather than exposed as a reusable library target.

=== Executable

Target `syncterm_app` produces the `syncterm` executable.  It owns process
startup/shutdown ordering: command parsing, application paths, settings,
display and logical consoles, fonts, themes, audio runtime, hyperlinks,
session history, and the Wren host.  It links `st_console_main` where that
platform entry wrapper exists.

Keep executable code as orchestration.  Reusable parsing, policy, state, or
mechanisms belong in the narrow component which owns them, with a public header
only when another target is a real consumer.  Early command tests are
`syncterm_help`, `syncterm_version`, and `syncterm_terminfo`; they do not prove
interactive backend or connected-session behavior.
