= Wren coverage of SyncTERM's native C interfaces

Status: accounting complete against commit da27a6e (2026-11-02).
The bindings are not complete. This report accounts for their coverage and
limitations; it does not authorize implementing every omitted C facility.

== Result and how to read this report

The review covers 80 project-owned public headers, 2,432 named native items,
and 119 explicitly excluded implementation/vendor/test headers. Every inventoried
item has a disposition. There are 51 finding topics, including broader API-scope
decisions, plus one stale documentation finding. The numbers follow the inventory;
they are not a stopping rule or a percentage of useful capabilities covered.

Important concrete results include loss of SFTP listing metadata, BBS provenance
and diagnostics, mutation/cache failure details, and custom-font codepage choices;
missing offscreen pixel compositing; and a transfer upload path API that bypasses
the File-grant abstraction. Other omissions, such as general audio, HTTP, INI,
cryptographic and Unicode utility APIs, require a scope decision rather than an
automatic new binding. The findings below distinguish these cases.

The complete per-symbol mapping is
link:api/wren-c-api-coverage.tsv[the native symbol ledger]. Each row records its
header, source line, native signature/field type/macro body, and assessment id.
link:api/wren-c-api-assessments.json[Assessment metadata] supplies the corresponding
Wren operation, VM availability, ownership/limits, source evidence and disposition.
The header matrix below makes the denominator and exceptions inspectable without
reading thousands of declarations. It is deliberately not a direct-C-call count.

== Scope and preserved contracts

The baseline is the modern standalone CMake project. The legacy Synchronet tree
is reference material, not another API to port. Inventory discovery examines
every header under +src+ and records either an inclusion or an explicit exclusion.
The metadata lists every excluded path with its owning mechanism and reason.
Private terminal/RIP protocol engines, console backends, raw SSH adapters, bundled
Wren/regex internals, immutable generated data, frontend ABI and test-control
headers are excluded from independent script ownership. Public terminal protocol
behavior is accessed through the active parser; this accounting does not propose
one foreign method per escape sequence or duplicate the terminal conformance work.

Operations, public fields (including value-embedded structs), result/error data,
enums, macros, callbacks, and extern values are inventoried. Opaque/type aliases
are assessed through their owner and signatures; standard C storage aliases are
not additional script features. Macro-generated collection families are accounted
through the full declaration/definition macro and collection assessment, rather
than counting every prefix expansion as a new capability. Header digests also
cover enum values, conditional branches, typedefs, limits and contract comments.

The extraction uses native Clang and generated CMake headers. All libc string
fallback declarations are forced on; textual macros retain every alternative and
complete multiline body. The remaining platform conditionals change native thread,
socket and ssize_t representation, not the portable function contracts. These are
explicitly reviewed in +conditional_interfaces+ in the metadata. This is not a
Windows execution result or proof of every backend implementation.

Existing boundaries define which omissions are intentional:

* The trusted menu VM owns directory/settings selection and application UI.
* Each connected VM owns its current session, with explicit SessionLease,
  WireLease, Operation and remote-file/directory lifetimes. It cannot enumerate
  other entries, change global settings or establish another connection.
* The isolated picker VM brokers selection and metadata, cannot open files,
  and cannot import the menu API. Declarations alone do not grant a capability.
* Native filesystem grants and token signing remain host authority. Supplying
  a pathname is not supposed to mint arbitrary access; the transfer finding
  identifies where the current API fails to maintain that abstraction.
* Host text boundaries validate UTF-8 and normalize NFC, including configuration
  credential fields and paths. Raw byte payloads remain bytes. Wren Strings retain
  standard arbitrary-byte semantics; no language normalization or Fiber changes
  are proposed.
* Native numeric quantities use checked conversions into the exact binary64
  integer domain, plus protocol/size limits. Wider C integer storage does not
  justify silent rounding or an implicit new Wren numeric representation.
* Device/process/display/worker/pointer ownership belongs to the application.
  Script values or higher-level owners can replace C allocation/free calls.
  This does not justify hiding an independently useful field or operation.

== Dispositions

Covered::
A usable Wren operation/value represents the native capability within its stated
VM, numeric and ownership contract, including higher-level equivalents.

Partial::
An operation/workflow exists, but native choices, data, errors or modes are lost.
The assessment identifies the limitation and links to a finding topic.

Unmapped::
No usable equivalent exists. This records an omission, not an implementation
mandate. Standalone utility/service relevance is explicitly left for scope review.

Host-owned::
Native orchestration, backend/transport, embedding, allocation or synchronization
belongs to a named existing owner. There is no second script pointer/worker owner.

Language-equivalent::
Wren values or standard operations replace native storage/collection mechanisms.
An arbitrary algorithm is not called covered merely because Wren could implement
it. In particular, a raw String-keyed Map is not canonical caseless comparison;
that behavior requires the existing explicit +Text.caselessKey+ operation.

Successful operation coverage and error/result fidelity are separate dimensions.
For example, ThemeDocument.save preserves its document error code, while most
other theme operations return an error String. Copying opaque Cell flags preserves
them, but does not let scripts inspect or set every native style bit.

== Findings: represented capabilities with mapping gaps

These are observations of current behavior, not approvals to change it. A missing
field can need a getter, an operation can need a different owner/result, or the
user may decide the restriction is appropriate. No gap is implemented here.

[[finding-bbs-cache-result]]
=== Successful BBS mutation hides cache-maintenance failure

+bbs.cache-result+ (partial; menu). Wren: DirectoryEntry.save/delete/rename return primary success.

The native mutation result can report cache_status after a committed list change. The binding does not inspect that secondary status, so scripts cannot distinguish complete cache maintenance from committed data with cache failure.

Evidence: link:../src/config/bbs_list/st_bbs_list.h[src/config/bbs_list/st_bbs_list.h:58]; link:../src/scripting/wren_host/wren_bind_menu.c[src/scripting/wren_host/wren_bind_menu.c:4243].

[[finding-bbs-diagnostics]]
=== Nonfatal BBS-load diagnostics are unavailable

+bbs.diagnostics+ (unmapped; menu). Wren: Menu.load has only coarse read status.

No query for nonfatal per-source/per-section load diagnostics and their native status is exported.

Evidence: link:../src/config/bbs_list/st_bbs_list.h[src/config/bbs_list/st_bbs_list.h:114]; link:../scripts/syncterm_menu.wren[scripts/syncterm_menu.wren:4].

[[finding-bbs-provenance]]
=== BBS entries lose detailed source provenance

+bbs.provenance+ (partial; menu). Wren: DirectoryEntry.type / profile.source.

Native PERSONAL/SHARED/WEB_SYSTEM/WEB_NAMED becomes personal versus system. source_name is not retained in the script model. Scripts cannot identify which named list provided an entry. Shadowed entries are intentionally absent from the merged visible list, but there is no script inspection API for that hidden provenance.

Evidence: link:../src/config/bbs_list/st_bbs_list.h[src/config/bbs_list/st_bbs_list.h:28]; link:../src/scripting/wren_host/wren_bind_menu.c[src/scripting/wren_host/wren_bind_menu.c:167].

[[finding-bbs-refresh-progress]]
=== Web-list refresh loses per-item progress and outcomes

+bbs.refresh-detail+ (partial; menu). Wren: Menu.refreshWebList returns success/error String.

Menu exposes refresh of a configured list but not native per-item queued/active/complete/failed state, phase, received/total/total_known, status and outcome progress records. The synchronous menu workflow does not provide an observer callback.

Evidence: link:../src/config/bbs_list/st_bbs_list.h[src/config/bbs_list/st_bbs_list.h:68]; link:../scripts/syncterm_menu.wren[scripts/syncterm_menu.wren:132].

[[finding-cell-style-flags]]
=== Cells preserve but cannot inspect or edit every native style flag

+console.style-bits+ (partial; same VM as the owning API). Wren: Cell bright/blink/legacyAttr/pixelGraphics; Screen.attr.

Native public style flags include underline, bold, reverse, conceal, double-height and teletext presentation controls. Wren exposes bright/blink, legacy colour attributes and readonly pixelGraphics, but no complete flag inspection/editing interface. Opaque Surface copy preserves them; that is not script control. Dirty/reserved and renderer-resolved flags remain host bookkeeping.

Evidence: link:../src/media/console/st_console.h[src/media/console/st_console.h:58]; link:../scripts/syncterm.wren[scripts/syncterm.wren:834].

[[finding-clipboard-url-capabilities]]
=== Clipboard and URL capability queries are missing

+console.clipboard-url-caps+ (partial; same VM as the owning API). Wren: Clipboard / Menu.openUrl / hyperlink operations.

Clipboard and URL operations exist but their native capability bits have no ScreenSupports query. Operation availability cannot be inspected in the same way as palette/pixels/font capabilities.

Evidence: link:../src/media/console/st_console.h[src/media/console/st_console.h:465]; link:../scripts/syncterm.wren[scripts/syncterm.wren:47].

[[finding-connection-setup-result]]
=== Connection setup has no structured script result

+connection.setup-diagnostics+ (partial; menu/application setup). Wren: host setup UI and protocol logs; ConnError for queued sends.

Structured native setup error code/phase/native_error/has_native_error/detail/presented and progress-state enum are not queryable as a script connection-attempt result. Host prompts/logs cover user-facing setup but do not preserve a machine-readable result for Menu.connect selection. ConnError is a different active-send error contract.

Evidence: link:../src/net/connection/st_connection.h[src/net/connection/st_connection.h:106]; link:../scripts/syncterm.wren[scripts/syncterm.wren:1124].

[[finding-console-operation-results]]
=== Drawing and state operations do not preserve native error distinctions

+console.operation-status+ (partial; same VM as the owning API). Wren: Screen/Palette/CustomCursor/VideoFlags drawing and state operations.

Successful drawing/state behavior has equivalents, but native int-returning methods generally become void/null/Bool or a Fiber abort with text. Native IO_ERROR distinctions are not uniformly retained as typed results. Capability guards and validation exist; they do not provide a lossless native error API. Pointer releases and native void-returning lifecycle methods are not affected by this finding.

Evidence: link:../src/scripting/wren_host/wren_bind_core.c[src/scripting/wren_host/wren_bind_core.c:4260]; link:../src/scripting/wren_host/wren_bind_core.c[src/scripting/wren_host/wren_bind_core.c:2825].

+cterm.operation-status+ (partial; same VM as the owning API). Wren: CTerm.write/sendKey.

Text write and semantic key injection preserve successful behavior and handled/not-handled, but native status and partial consumed count become generic Fiber abort messages. The caller cannot inspect the native failure code. Raw wire/decoder ownership remains native.

Evidence: link:../src/scripting/wren_host/wren_bind_session.c[src/scripting/wren_host/wren_bind_session.c:1003]; link:../src/scripting/wren_host/wren_bind_session.c[src/scripting/wren_host/wren_bind_session.c:983].

[[finding-cterm-reset-contract]]
=== Direct terminal reset has no matching public contract

+cterm.reset+ (partial; same VM as the owning API). Wren: CTerm.write can send reset escape sequences.

No dedicated script operation invokes st_cterm_reset_terminal or returns its native reset status. That function finishes pending input, resets parser state and rebuilds the RIP engine. CTerm.write can submit protocol reset sequences through the current parser, but does not expose this complete host reset transaction or its failure result.

Evidence: link:../src/terminal/cterm/st_cterm.c[src/terminal/cterm/st_cterm.c:2674]; link:../scripts/syncterm.wren[scripts/syncterm.wren:1228].

[[finding-digest-algorithms]]
=== File hashing omits SHA-2 and generic digest input

+utility.digest+ (partial; menu/connected grant owners; no file opening in picker VM). Wren: File.sha1 / File.md5.

Only two file digest algorithms are exposed. SHA-256/384/512, generic byte-buffer digest input and digest-size query are absent. File methods are grant-confined and return raw digest bytes.

Evidence: link:../src/base/crypto/st_digest.h[src/base/crypto/st_digest.h:18]; link:../src/scripting/wren_host/wren_bind_fs.c[src/scripting/wren_host/wren_bind_fs.c:1294].

== Confirmed equivalents and intentional ownership

Some tempting gap claims were ruled out by following the actual abstraction:

* +Timer.now+ already returns monotonic seconds. +Timer.after+ handles waits;
  standard +System.clock+ provides process CPU time. No clock API was added.
* +VideoFlags.expand+ correctly lacks a live setter: the native setter rejects
  changing that creation-time flag. +lineGraphicsExpand+ is independently mutable.
* All fifteen SFTP provider operations have equivalents. Request ids and numeric
  handles become owned Operation/RemoteFile/RemoteDirectory objects; byte/list
  sizes are language counts. The listing stat-field loss remains a real exception.
* Profile configuration, DirectoryEntry persistence metadata and Session runtime
  state are separate objects. Missing duplicate setters on every object are not
  missing native fields. Defaults intentionally exclude entry scripts.
* Hyperlink GC roots, thread/event/semaphore objects, socket/TLS workers, audio
  hardware, display activation and VM create/destroy belong to their host owners.
* Image PPM/PBM/JXL decoding, pixel masks/planes/descriptors, Cell/Surface copying,
  scrollback row copying, theme documents/undo, menu models and semantic connection
  send operations have usable higher-level APIs. Their individual exceptions and
  error limits are retained in the ledger rather than concealed by this summary.

== Consumers, tests and limits of verification

Source-level evidence is not replaced by test names. The metadata pins assertion
anchors for SFTP error payloads and cancellation/close completion; filesystem
success/failure and link rejection; native and Wren video-flag behavior; Settings
safe-mode KDF behavior; and the standard VM String behavior. It also records
bundled consumers: the main menu/profile/settings/theme editors, font picker,
transfer picker/App, SFTP browser/queue, UI dispatcher and core helper tests.

Dispatch order was checked in +st_wren_bind_method+: session/VM-specific methods
precede core fallbacks, and a declared method in another VM does not supply that
VM's capability. For example, the menu's CTerm fallback is not evidence that a
connected CTerm state query is constant. The connected binder reads the real
terminal state.

Verification performed on FreeBSD 15.1-RELEASE-p5 amd64 with Clang 19.1.7,
C17, the native Debug CMake configuration and +ST_CONSOLE_TEST=ON+:

* Configured the standalone project and built +syncterm_app+, the host, menu
  settings, loader and picker test targets, and all four VM test targets.
* All 26 Wren CTests passed: four +st_wren_vm_*+ tests; host, menu, settings,
  live SFTP, picker and directory contracts; seven loader/model/core cases;
  and eight synthetic UI suites. Inherited desktop display/session variables
  were cleared; these tests used their headless/control backends.
* The ledger checker reproduced all 80 headers / 2,432 items and checked all
  dispositions, evidence anchors/digests and 119 explicit header exclusions.
  The full inventory also includes forced libc capability-absent declarations.

No Windows runtime, real audio-device or exhaustive per-native-option coverage
is claimed. Tests corroborate the specified paths; static declaration/dispatch/
implementation review establishes the reported omissions. No regression tests
were invented for methods which do not exist, and no native binding or Wren
language behavior was changed.

== Rechecking and future edits

From the repository root, after configuring a native CMake build:

[source,sh]
----
cmake -S . -B build-wren-input -DCMAKE_BUILD_TYPE=Debug -DST_CONSOLE_TEST=ON
python3 tools/audit/wren_c_api_coverage.py --check --build-dir build-wren-input
----

+--extract+ emits the current Clang inventory instead. The checker refuses missing
or duplicate symbols, unclassified/unused assessments, header/symbol/type/line
changes, changed exclusion sets, and missing/changed evidence. It is an accounting
drift check, not an automatic proof of semantic coverage. A changed header or
binding must be reviewed before updating its digest/disposition; regenerating an
empty inventory does not count as review. This report is a durable accounting,
not an implementation checklist to delete after the review.
