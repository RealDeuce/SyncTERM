= SyncTERM

SyncTERM is a terminal emulator for connecting to bulletin board systems.

== Build

Run from the repository root, using an out-of-source CMake build:

[source,sh]
----
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
----

The executable and libretro core are in `build/bin/`. Multi-configuration
generators use `build/bin/<configuration>/`. After the source reorganization,
configure a fresh build directory rather than reusing a pre-move build tree.

On macOS the application is `build/bin/SyncTERM.app`, including its Finder
icon and application metadata. Launch it from Finder or with
`open build/bin/SyncTERM.app`; for command-line arguments invoke
`build/bin/SyncTERM.app/Contents/MacOS/SyncTERM` directly. Multi-configuration
generators put the bundle below `build/bin/<configuration>/`. CI artifacts
contain the complete bundle alongside `syncterm_libretro.dylib`.
Dependency source/linkage settings still apply; the bundle does not embed
externally selected shared libraries. URL-scheme registration metadata is
included, but handling incoming macOS URL-open events is not implemented.

For process-controlled bitmap tests of the regular executable, configure with
`-DST_CONSOLE_TEST=ON`. See link:docs/TEST_CONTROL.md[the testing driver guide]
for the Python client, coherent cell/pixel captures, and pipe protocol.

== Repository layout

Application sources live directly in `src/`, with their tests in `src/tests/`.
Libraries keep their own CMake targets, tests, licenses, and data under:

[cols="1,3",options="header"]
|===
| Directory | Responsibility
| `src/base/` | Collections, strings, conversions, threading, timing, and basic utilities
| `src/text/` | UTF-8, codepages, and Unicode processing
| `src/io/` | Files, paths, locking, mappings, and serial devices
| `src/net/` | Sockets, connections, TLS, downloads, SFTP, and transfer protocols
| `src/media/` | Audio, pixels, console rendering, images, and fonts
| `src/terminal/` | Emulation, terminal sessions, screen modes, history, and hyperlinks
| `src/config/` | Profiles, settings, BBS lists, themes, and configuration storage
| `src/scripting/` | Wren integration and its VM and regular-expression dependencies
|===

`scripts/` contains runtime Wren modules. `cmake/` contains build helpers,
and `ci/` contains CI drivers and their tests.

See link:docs/Manual.txt[the user manual], link:docs/HACKING.adoc[the development
guide], and link:docs/Wren.adoc[the Wren API manual]. Development rules are in
link:AGENTS.md[AGENTS.md]. Licensing information is in link:LICENSE[LICENSE]
and the component notices.

MIDI backends, runtime/static linkage, and ANSI music translation are
described in link:docs/MIDI_PLAYBACK_DESIGN.adoc[the MIDI playback design].

== Optional Wren interfaces

link:addons/modern_ui/README.md[Modern UI] is an independently installed
directory and settings frontend with a searchable directory, connection
details, and graphical chrome. It uses the external main-menu override; its
scripts are not embedded in SyncTERM. Build its installable ZIP with
`cmake --build build --target syncterm_modern_ui_addon`. See its README for
installation, removal, capabilities, and the current renderer limits.
