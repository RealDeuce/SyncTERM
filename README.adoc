= SyncTERM

SyncTERM is a terminal emulator for connecting to bulletin board systems.

Automated development builds for Linux x86-64, Windows x86-64, and macOS ARM64,
x86-64, and universal (ARM64 + x86-64) are available from the
https://github.com/RealDeuce/SyncTERM/releases/tag/latest-build[GitHub mirror's latest-build prerelease].
They are replaced after successful upstream builds and expire after 14 days.
See link:docs/HACKING.adoc#_github_mirror_development_downloads[the download workflow]
for fixed download URLs and details.
GitLab also provides link:docs/HACKING.adoc#_gitlab_development_downloads[binary-only
ZIPs from the latest successful pipeline] for its native and cross-build jobs.

== Bugs, feature requests, and support

Reports and support conversations are handled through SourceForge. Choose
the tracker that matches your question:

* https://sourceforge.net/p/syncterm/tickets/[Bugs]: report crashes,
  incorrect behaviour, and regressions. Include the SyncTERM version or
  development build, operating system, display backend, steps to reproduce,
  and what you expected to happen. Relevant logs, sample terminal output,
  and screenshots help make a report reproducible.
* https://sourceforge.net/p/syncterm/feature-requests/[Feature Requests]:
  propose new capabilities or changes to existing behaviour. Describe the
  problem you want to solve and the desired result. Requests are reviewed
  for fit with SyncTERM's design; the eventual implementation and naming
  may differ from the original suggestion.
* https://sourceforge.net/p/syncterm/support-tickets/[Support]: ask about
  installation, building, configuration, or using SyncTERM. If you are
  unsure whether something is a bug or a usage question, start here.

Search existing tickets, including closed ones, before opening a new topic.
Add details to an existing matching ticket and keep each new ticket focused
on one issue or request. Follow-up questions, implementation updates, and
resolutions belong in the same ticket. A fix in development may precede a
release; check the build or version mentioned in the ticket.

For font artwork, use the https://font.syncterm.net/[Glyph Foundry] to draw
or improve glyphs at SyncTERM's supported sizes and preview their appearance.
Submissions create public
https://sourceforge.net/p/syncterm/glyphs/[Glyph Submissions] tickets for
review before inclusion in the bundled fonts. Use the Bugs tracker for
rendering problems, including the affected text and a screenshot when possible.

== Build

Run from the repository root, using an out-of-source CMake build:

[source,sh]
----
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
----

The executable and libretro core are in `build/bin/`. Multi-configuration
generators use `build/bin/<configuration>/`. After the source reorganization,
configure a fresh build directory rather than reusing a pre-move build tree.

On macOS the application is `build/bin/SyncTERM.app`, including its Finder
icon and application metadata. Launch it from Finder or with
`open build/bin/SyncTERM.app`; for command-line arguments invoke
`build/bin/SyncTERM.app/Contents/MacOS/SyncTERM` directly. Multi-configuration
generators put the bundle below `build/bin/<configuration>/`. CI artifacts
contain the complete bundle alongside `syncterm_libretro.dylib`.
Dependency source/linkage settings still apply; the bundle does not embed
externally selected shared libraries. URL-scheme registration metadata is
included, but handling incoming macOS URL-open events is not implemented.

For process-controlled bitmap tests of the regular executable, configure with
`-DST_CONSOLE_TEST=ON`. See link:docs/TEST_CONTROL.md[the testing driver guide]
for the Python client, coherent cell/pixel captures, and pipe protocol.

== Repository layout

Application sources live directly in `src/`, with their tests in `src/tests/`.
Libraries keep their own CMake targets, tests, licenses, and data under:

[cols="1,3",options="header"]
|===
| Directory | Responsibility
| `src/base/` | Collections, C string portability, conversions, threading, timing, and basic utilities
| `src/text/` | ASCII operations, UTF-8, codepages, and Unicode processing
| `src/io/` | Files, paths, locking, mappings, and serial devices
| `src/net/` | Sockets, connections, TLS, downloads, SFTP, and transfer protocols
| `src/audio/` | Audio backends, mixing, music, and file playback
| `src/graphics/` | Pixel operations and image codecs
| `src/fonts/` | Font data, loaders, and catalog
| `src/console/` | Console rendering, input, and display backends
| `src/terminal/` | Emulation, terminal sessions, screen modes, history, and hyperlinks
| `src/config/` | Profiles, settings, BBS lists, themes, and configuration storage
| `src/scripting/` | Wren integration and its VM and regular-expression dependencies
|===

`scripts/` contains runtime Wren modules. `cmake/` contains build helpers,
and `ci/` contains CI drivers and their tests.

See link:docs/Emulations.adoc[the terminal emulation manuals] for protocol
syntax, commands, replies and compatibility limits.

See link:docs/Manual.txt[the user manual], link:docs/HACKING.adoc[the development
guide], and link:docs/Wren.adoc[the Wren API manual]. Development rules are in
link:AGENTS.md[AGENTS.md]. Licensing information is in link:LICENSE[LICENSE]
and the component notices.

MIDI backends, runtime/static linkage, and ANSI music translation are
described in link:docs/MIDI_PLAYBACK_DESIGN.adoc[the MIDI playback design].

== Optional Wren interfaces

link:addons/modern_ui/README.md[Modern UI] is an independently installed
directory and settings frontend with a searchable directory, connection
details, and graphical chrome. It uses the external main-menu override; its
scripts are not embedded in SyncTERM. Build its installable ZIP with
`cmake --build build --target syncterm_modern_ui_addon`. See its README for
installation, removal, capabilities, and the current renderer limits.
