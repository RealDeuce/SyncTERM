= Amiga Workbench font references

These are unmodified native font files retained for comparison only. Nothing
in this directory is compiled into SyncTERM or installed with it. The bitmap
catalog still comes from `../data/manifest.json` and its selected YAFF inputs.
The original Commodore/Agfa font data is separate from the license on the
analysis script.

`workbench-1.3/` contains 30 bitmap strikes and ten family descriptors from
the Workbench and Extras disks. Original filename case is preserved.
`workbench-2.1-3.1/` contains the shared later set: 30 bitmap strikes, ten bitmap
family descriptors, and nine outline font files (CGTimes, CGTriumvirate and
LetterGothic). All 49 files are byte-for-byte identical between the sampled
2.1 Fonts disk and the local 3.1 Fonts disk, so there is only one copy here.
An independently archived 3.1 Fonts disk also agrees on all 30 bitmap strikes
and ten bitmap descriptors; that image does not contain the outline fonts.
Whole disk images, icons and the `_bullet` support files are not retained.

Topaz/8 and /9 are ROM fonts and are not included in either disk reference set.
No Kickstart ROM is retained here.

== Which fonts did syncterm-skypix supply?

The comparison uses https://github.com/SpitfireTN/syncterm-skypix[the supplied
repository] at commit `647972fb9789deb5942f471b51a43be85578eafe`.

* All 30 stock native strikes in `fonts/amiga-font/` exactly match the
  Workbench 2.1/3.1 files, including their SHA-256 hashes. None matches the
  corresponding 1.3 file. These identical fonts cannot establish whether
  the supplier copied a 2.1 or a 3.1 disk.
* Four additional native files are absent from all three sampled releases.
  Their embedded version strings identify Courier/30 and /36, and Times/30
  and /36, as AWeb 39.0 fonts dated September/October 1996.
* There are 37 SPF2 files, each containing only ASCII bytes 32 through 126.
  The 33 with native counterparts have identical normalized glyph shapes,
  advances and baselines to those counterparts. SPF2 has no bearing or
  nominal-width field, so this does not establish identical text placement.
* Of the 29 SPF strikes also present on the Workbench disks, 28 have the later
  baseline rather than the 1.3 baseline. Garnet/9 has the same baseline,
  printable glyph shapes and printable advances in both disk sets, so its
  ASCII-only SPF cannot distinguish them.
* Pearl/8, Sapphire/15, Sapphire/18 and Topaz/8 have no native counterparts in
  the supplied collection and no files in these disk references. This
  comparison does not assign them a disk origin.

== The compiled catalog is a separate comparison

The `workbench-3.1_` YAFF filenames are provenance labels, not proof that the
resulting compiled fonts match the original 3.1 files. The script reconstructs
the selected YAFF inputs and overrides, then checks every glyph, advance,
placement, baseline and nominal width against the actual compiled catalog's
FNV-1a-64 inventory. All 39 compiled entries were verified this way.

[cols="2,3,4",options="header"]
|===
| Group | Supplied native versus disk | Compiled catalog versus disk
| Emerald, Garnet, Helvetica, Opal, Sapphire/14 and /19, Times/11 through /24,
  Topaz/11 (20 strikes)
| Exact later-file matches
| Exact later metrics, advances and positioned ink for all 256 byte mappings
| Ruby/8, /12, /15; Diamond/12, /20 (5 strikes)
| Exact later-file matches
| Later glyph shapes and advances, but nominal widths and baselines equal
  the 1.3 values retained through the JR-Comm overrides; ink sits one pixel
  higher relative to a common pen baseline than the later native fonts
| Courier/11, /13, /15, /18, /24 (5 strikes)
| Exact later-file matches
| Same glyph shapes and later baselines, but wider nominal cells and converted
  proportional advances/placement instead of the native fixed advances
| Courier/30, /36; Times/30, /36 (4 supplied extras)
| AWeb 1996 additions, absent from the sampled Workbench disks
| Glyph shapes agree for ASCII; some advances, positions or nominal widths
  differ. These are not evidence about stock Workbench fonts
|===

For example, native Courier/11 has nominal width 6 and baseline 8; the compiled
font has nominal width 8 and baseline 8, with different advances for 53 of
95 printable ASCII glyphs. Native Ruby/8 has width 11 and baseline 5; the
compiled font has width 15 and baseline 6, matching the 1.3 metric values.
Ruby/8 is still a mixture: its fallback/control glyph shapes and advances
agree with the later font rather than the 1.3 file. None of the 30 compiled
stock strikes exactly matches the entire corresponding 1.3 font.

`specimens.svg` shows ten representative strikes at a common pen baseline
in four columns: 1.3 disk, 2.1/3.1 disk, compiled SyncTERM, and supplied native.
It contains literal unstyled pixels from the respective data, without
scaling algorithms or screen captures. Each source pixel is displayed at 2x.

== What changed from 1.3 to 2.1/3.1?

Both generations contain the same bitmap family/size inventory:

[cols="1,3",options="header"]
|===
| Family | Pixel heights
| Courier | 11, 13, 15, 18, 24
| Diamond | 12, 20
| Emerald | 17, 20
| Garnet | 9, 16
| Helvetica | 9, 11, 13, 15, 18, 24
| Opal | 9, 12
| Ruby | 8, 12, 15
| Sapphire | 14, 19
| Times | 11, 13, 15, 18, 24
| Topaz | 11
|===

All 30 bitmap files changed on disk. Topaz/11 was substantially redrawn:
64 of 95 printable ASCII glyph shapes differ after removing translation.
The other 29 strikes retain the same printable ASCII glyph shapes and
advances. Most of their shape changes affect fallback/control bytes, with
some changes at byte 0xA0. Raw raster widths and bearings can change without
changing the visible shape or advance. Baselines decrease by one in 28
strikes (all except Garnet/9 and Topaz/11), and 24 nominal widths change.
Consequently, matching alphabet pictures alone does not establish matching
font behavior. The later disks also provide the three outline families above.

== Sources and reproducibility

`manifest.json` records every retained file's original disk path, size and
SHA-256, together with source-image SHA-256/SHA-1 values and download URLs.
Archived images were obtained from the
https://amigamuseum.emu-france.info/Fichiers/ADF/Installation,%20Kickstars,%20Workbench%20Tutorials%20%26%20Promotional/[Amiga Museum disk index].
The local 3.1 source is `~/FS-UAE/Floppies/wb31-fonts.adf`.

Images were opened read-only with amitools 0.8.1, and only font files were
extracted. The source labels are recorded as found, with these qualifications:

* The 1.3 boot image matches MAME's `wb13_dk` Workbench 34.20 image; the
  sampled Extras image has no SHA-1 match in that catalogue snapshot.
* The 2.1 Fonts download is labelled 38.36 by the archive, while its SHA-1
  matches MAME's `wb21_3835` Fonts image (`370160-01_fonts.adf`). Font version
  strings are 37.1 or 37.2, dated January or March 1991.
* The 3.1 images have different disk hashes, while the shared font files
  agree exactly. The comparison makes file-level claims, not a claim that
  every sampled disk is an untouched retail master.

The catalogue snapshot's SHA-256 and
https://github.com/mamedev/mame/blob/master/hash/amiga_workbench.xml[upstream URL]
are retained in the manifest. The
https://wiki.amigaos.net/wiki/AmigaOS_Manual:_Workbench_Fonts[Workbench font manual]
describes the bitmap/outline split and ROM Topaz. Decoding follows the native
TextFont character-location, kerning and spacing tables; native files are
never executed.

`comparison.json` contains the disk-to-disk and disk-to-compiled comparisons.
`skypix-comparison.json` pins all 34 supplied native files and 37 SPF files
and records their separate comparisons. Byte lists distinguish shape changes
from advances and positioned ink; the default glyph is also compared for
native fonts. SPF positioned ink assumes left alignment only, because the
format does not preserve the native bearing.

To regenerate with amitools 0.8.1 available to Python:

[source,sh]
----
cmake -S . -B build
cmake --build build --target st_amiga_font_test
python3 src/media/amiga_font/reference/compare.py \
    --builtins build/src/media/amiga_font/st_amiga_font_test \
    --skypix ~/src/syncterm-skypix
----

Add `--check` to verify the manifest, generated reports, compiled inventory
and specimen SVG without rewriting them. The script reads the supplied
checkout; it does not change or copy that checkout into this directory.
