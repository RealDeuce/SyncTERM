= SyncTERM Console Library

== Introduction

The `st_console` library is SyncTERM's character-generator and host-console
abstraction.  It owns a grid of character cells, optional software pixel
planes, fonts, palettes, input events, presentation state, and one selected
host backend.

It is not a Borland `conio` compatibility library.  It does not expose global
screen state, `putch`, `cprintf`, conio windows, or line editing.  Those
operations are either explicit operations on an `st_console_t` instance or
belong to a higher-level user-interface component.  Terminal parsing and
emulation are also separate; CTerm consumes a connection's byte stream and
writes the resulting cells and pixels through this interface.

An application may attach multiple logical consoles to one
`st_console_display_t`.  The display owns the physical backend, window or host
terminal, presentation worker, and physical-key state.  Each `st_console_t`
retains its own cells, pixels, palette, fonts, cursor, dimensions, title,
pointer preference, update state, and ordered input queue.  Exactly one console
is active on a nonempty display at a time.

`st_console_display_config` holds backend selection, text-terminal encoding
and I/O, an optional RGBA application icon, and initial window size/scaling.
The icon storage remains owned by the caller for the display's lifetime and is
ignored by non-window backends.  `st_console_config` holds only the logical
console's cell/raster geometry and rendering policy.  The convenience
constructor is `st_console_create(result, display_config, console_config)`;
applications sharing one output instead create a display and attach logical
consoles with `st_console_create_on_display()`.  Initial window settings apply
when the first console opens the backend, not when another console attaches
or becomes active.  Switching consoles preserves the current display scale.

`st_console_display_activate()` synchronously applies the selected console's
retained mode and state and completes a full presentation.  Inactive consoles
can be updated and rasterized without invoking backend callbacks.  Events stay
queued on whichever console was active when they arrived.

Input routing changes only after successful activation.  A failed activation
restores the previous console's dimensions, palette, title, pointer preference,
and presentation.  If that restoration also fails, the previous console remains
selected but backend operations return `IO_ERROR_IO` until an explicit
activation succeeds.  The application may continue using retained logical
state; it must not assume the physical output is current while suspended.

Attachment, activation, and destruction are serialized per display.  Destroying
the selected console selects a remaining peer and drains library-owned input
and presentation references before freeing memory.  If presenting that peer
fails, it remains selected with physical output suspended until a successful
activation.  Destroying the last console shuts down the physical backend; the
display object itself can subsequently accept a new first console.
If a failed backend cannot detach from a removed console, its storage remains
internally retained until successful activation or backend shutdown.  The
removed handle is invalid to callers regardless of this deferred release.

Public operations on a live instance may be called concurrently.  Read-only
state queries share a reader lock; mutations, presentation, and backend
operations are serialized.  The owner must prevent new calls and allow active
calls to finish before calling `st_console_destroy()`.

== Output Modes

An output mode selects how the retained console state reaches the user.  It is
separate from the screen mode, which defines the grid, character generator,
raster, cursor, blink rules, and intended aspect ratio.

=== Automatic Selection

The caller may request `ST_CONSOLE_BACKEND_AUTO`; it does not need to prepare
backend-specific supporting state.  For a bitmap console, selection prefers
the native GDI or Quartz implementation, then Wayland, X11, and SDL where they
were built and are usable.  The fallback text path tries ncurses and then
ANSI.  A text-only Windows configuration can select the native Win32 console.
Failure to load an optional runtime library falls through to the next usable
backend.

`st_console_get_backend()` reports the selected backend.
`st_console_build_features()` reports what was compiled into the library; it
does not promise that an optional display server or runtime library is usable
on the current host.

The Wayland backend waits without a client-side deadline for the compositor's
mandatory initial configure event during creation.  Once running, loss of the
compositor posts one close event and makes pending and later backend operations
fail.  Clipboard source delivery writes the complete payload to the descriptor
supplied by Wayland; a closed receiver abandons that transfer without raising
`SIGPIPE`, while an open receiver applies the protocol's ordinary write
backpressure.

=== Text Backends

Text backends display retained cells but cannot display arbitrary pixel-plane
changes or registered bitmap fonts.  ANSI Unicode mode and wide ncurses emit
the retained Unicode scalar; CP437 modes encode that scalar through the
locale-independent CP437 table and use `?` when it is not representable.
Bitmap glyph indexes never select text-terminal characters.  Continuation
cells for wide glyphs are skipped.

ANSI direct-colour support and indexed-colour count are separate
capabilities.  The ordinary terminal path reads terminfo and also accepts
`COLORTERM=truecolor` or `COLORTERM=24bit` when terminfo does not advertise
RGB.  Indexed cells stay indexed even on a direct-colour terminal.

The ordinary ANSI backend reads and writes the process standard streams.
Input may be an interactive terminal or a redirected pipe or regular file;
output remains an ANSI byte stream when redirected.  End-of-file or a
permanent input error finishes any pending escape or UTF-8 input, posts one
`ST_CONSOLE_EVENT_CLOSE`, and stops the input worker.  Destroying the display
interrupts its input wait without posting a close event.  A caller-supplied
`st_console_ansi_io` replaces output only and does not provide an input
source.

ncurses uses its extended colour-pair interfaces when the required ncurses
6.1 symbols are present, so colour and pair identifiers are not narrowed to
signed 16-bit.  Palette entries changed through a mutable curses terminal are
restored when the instance closes.

`ST_CONSOLE_CAP_TEXT_TERMINAL` is set for ANSI, ncurses, and Win32 console.
`ST_CONSOLE_CAP_LOCAL_CONTROL_KEYS` is currently set only for ANSI and
ncurses, where SyncTERM reserves Ctrl+Q and Ctrl+S for local commands.  The
native Win32 console is a text terminal but has independent keyboard events.
`ST_CONSOLE_CAP_BRIGHT_BACKGROUND` is independent of palette mutation and
reports that the backend can present the sixteen-colour bright-background
interpretation.  For ncurses, complete 16-bit indexed-palette capability
requires a reported colour count of at least 65,535 together with the
extended colour and pair interfaces; direct colour is a separate path.

=== Bitmap Backends

Bitmap backends render the complete character-generator model, including
registered fonts, direct RGB, indexed palette changes, blink planes, custom
cursors, SAA5050 attributes, and pixel graphics.  The common bitmap presenter
tracks regional damage through font rasterization and every scaling stage so
small updates do not become full-frame uploads.

Desktop applications link `st_console_main`.  Its entry wrapper keeps APIs
which require the process main thread—currently SDL and AppKit/Quartz—on that
thread while running the application on a joined secondary thread.  Selecting
an automatic backend does not leak that requirement into application code.

X11, Wayland, xkbcommon, and optional SDL are loaded at run time; their
development declarations are build capabilities.  GDI and the Windows
console are part of the Windows programming environment.  AppKit and Quartz
are part of the macOS programming environment and are linked normally.

== Cells and Coordinates

Coordinates are zero-based.  Rectangles have nonzero width and height and
must fit entirely inside the current grid.  Strides are cell counts expressed
as `size_t`.

`struct st_console_cell` is compact and contains no pointers or separate
allocations.  It retains the resolved bitmap glyph, the selected and actual
internal font identifiers, indexed or direct-RGB colours, hyperlink identifier,
and named flag masks.  It does not retain the Unicode scalar or grapheme which
selected that glyph.  SAA5050 control data is retained in flags separately
from the displayed glyph.  The final `reserved` member is always zeroed by
callers and normalized by the console.  Together with compile-time offset and
size assertions, this defines a padding-free 24-byte cell representation for
internal raw rectangle checksums; it does not turn the structure into a
persistent or cross-version file format.

`ST_CONSOLE_CELL_BRIGHT` and `ST_CONSOLE_CELL_BLINK` retain source attribute
bits 3 and 7; `ST_CONSOLE_CELL_BOLD` remains an independent glyph-weight
style.  The two legacy-colour provenance flags mean the corresponding stored
base palette index should follow the console's video-flag policy.  An explicit
palette or RGB colour does not acquire that policy merely because its numeric
index is below eight.

The high colour bit selects direct RGB; otherwise values through 65,535 are
palette indices.  Cells and pixel planes use the same representation, so
palette identity survives rasterization, capture, snapshots, and blits.

`ST_CONSOLE_CELL_DIRTY` is private presentation state.  Writes ignore it from
callers and reads do not return it.  Content changes mark cells in the
low-bandwidth mutation path; the renderer consumes contiguous dirty runs.

Cell operations accept only resolved font/glyph cells.  Before constructing a
cell from semantic text, the caller resolves its normalized grapheme cluster
with `st_console_font_lookup_cluster()`; the scalar convenience lookup is
`st_console_font_lookup()`.  `st_console_write_cells()` applies normal
pair-aware cell mutation, while `st_console_write_complete_cells()` bulk-copies
a complete validated rectangle without per-cell pair synthesis.  Neither
operation interprets `cell.glyph` as a codepoint.

Readback returns the resolved cell, not the scalar or grapheme which selected
its glyph.  `st_console_font_glyph_text()` can provide a representative
registered mapping for text backends and selection, but that mapping is not
lossless provenance and is not required to reproduce the original input.

== Fonts and Unicode

Each font registration contains one-bit bitmap data and a sorted Unicode
mapping.  There is no implicit codepoint-to-glyph identity map, even for a
256-glyph legacy font.  A decoder first resolves legacy
source-bright/source-blink font selectors with
`st_console_font_for_flags()`, then looks up the resulting `(font,
codepoint)` pair.  These source bits are distinct from the bold style and
remain in the stored cell after font selection.

Lookup checks the selected font first, then font zero's Unicode fallback.  If
neither maps the scalar, font zero supplies a width-matched replacement.
Mapped width comes from font data; missing-scalar width comes from generated
Unicode East Asian Width and Emoji Presentation tables, never the process
locale or `wcwidth()`.

An eight-pixel glyph occupies one cell and a sixteen-pixel glyph occupies two.
The second cell is marked `ST_CONSOLE_CELL_CONTINUATION`, and region mutations
preserve complete pairs.  A wide glyph at the final column wraps before being
written when wrapping is enabled.  If it still cannot fit after the wrap, as
in a one-column text window, the glyph is suppressed after the normal line
advance or scroll.

Static registration borrows immutable process-lifetime data.  Copy
registration owns bitmap and mapping copies until console destruction, which
supports downloaded fonts and server-supplied Unicode maps.  If all 65,536
identifiers are occupied, a new registration replaces the least-recently-used
font, succeeds, and reports the replacement on standard error.  Existing
cells retain that identifier and are not dirtied merely by the replacement.
Registration never reinterprets retained cells; the new mapping applies to
subsequent lookups and Unicode cell writes.

== Stateful Text Operations

The current style, position, clipping/scroll window, wrapping, cursor, blink
mode, video flags, palette, and scaling policy are per instance.  Changing the
text window moves the position to its upper-left corner.

The seven video flags retain the legacy source-attribute policy without
changing the cell ABI.  Source bit 3 may select a bright foreground and/or an
alternate font; source bit 7 may select blink, a bright background, and/or an
alternate font.  `NO_BRIGHT` and `NO_BLINK` disable only their respective
rendering meanings.  `EXPAND` is fixed by the console geometry; when an
eight-pixel font is displayed in a nine-pixel cell, the ninth column is blank
except that `LINE_GRAPHICS_EXPAND` repeats column eight for glyph indices
0xC0 through 0xDF.  Changing a flag that affects existing presentation
invalidates retained rendering without rewriting cells or their resolved font
identifiers; selector changes apply to subsequent writes.

Filling the final column wraps immediately when wrapping is enabled; at the
bottom of the window that wrap immediately scrolls.  Carriage return moves to
the window's left edge, line feed retains the column and advances or scrolls,
tab writes spaces to the next eight-column stop, and backspace moves left and
replaces that cell with a styled space.

UTF-8 decoding is locale-independent.  A complete string is validated before
any cells change; overlong encodings, surrogates, incomplete sequences, and
values beyond U+10FFFF are rejected.  Formatted output is not part of this
layer.

Direct semantic codepoint writes apply the same Unicode-scalar requirement.
Codepoint arguments used by window clearing, scrolling, and line
insertion/deletion must occupy exactly one text column.  Cell arguments used by
rectangle fill and move-and-clear must already contain a resolved one-column
glyph.  Invalid semantic input or a wide fill is rejected before text or
cursor state changes.

Moves have snapshot source semantics when rectangles overlap.  Scrolling and
line insertion/deletion move matching cached glyph rasters with the cells, so
retained rows do not pass through the font renderer again.  A full-width
top-of-grid scroll advances a circular text-raster origin instead of copying
every pixel row.  Non-text raster margins never participate in the scroll.
If a horizontal text-window boundary crosses a wide pair, an affected row
operation clears the complete pair, including its adjacent half outside the
window, before moving the remaining complete cells.

== Pixel Planes and Scaling

Providing both cell dimensions creates software pixel planes; providing only
one is invalid.  Explicit raster dimensions may add non-text margins but
cannot be smaller than the text image.  Primary and alternate planes are the
two blink states.

Pixel writes first bring intersecting character rasters current, then modify
the final-raster planes and mark those cells as pixel graphics.  A later
character-content change regenerates the cell.  Text backends reject pixel
mutations rather than claiming success for invisible output.

If requested external scaling is unavailable (for example, X11 without
XRender or Wayland without viewport support), the same backend uses software
scaling.  Startup and console switching remain available, and neither the
console's requested mode nor the saved settings are changed by this fallback.

Internal scaling composes the final-size image in software; external scaling
hands a native-size retained frame to a capable host.  Aspect correction is
applied before the requested window scale, and creation never scales below
one displayed pixel per source pixel.

Blocky is the default scaling policy.  Pointy is the optional traditional
SyncTERM smoothing pipeline.  Integer multiplication, Pointy, xBR, and
one-axis interpolation are stages selected for the actual dimensions, not
three separate user-visible scalers.  The common case can expand one axis by
an exact integer while interpolating only the other.

Damage is transformed through each retained scaling stage.  Integer stages
multiply the rectangle, filters expand it by their dependency radius, and
interpolation uses precomputed inverse maps.  `st_scaler_benchmark` measures
full-frame and regional scaling; `st_console_benchmark` measures rasterization
and sustained scrolling.  They are comparison tools, not CTest thresholds.

== Presentation and Snapshots

Bitmap backends collect normal visible changes for up to 10 ms before
presenting them.  Small parser writes therefore accumulate dirty cells rather
than synchronously scaling and crossing into the window system each time.

`st_console_begin_update()` and `st_console_end_update()` provide explicit,
nestable batching.  The outermost end makes the batch eligible for normal
presentation.  `st_console_present()` is a synchronous forced boundary even
inside a batch.  On an inactive console it drains only the retained off-screen
state and does not invoke the display backend.  Text backends remain
synchronous so failures can be returned.

Wayland does not wait when both shared-memory buffers remain owned by the
compositor.  That presentation attempt is dropped successfully; a later
change presents the then-current retained state.

Snapshot creation is a drain boundary: pending changes are handed to the
backend and live dirty flags are consumed before the copy.  A snapshot retains
cells, pixel planes, palette, style, window, position, cursor, wrapping, and
video/scaling state, but never dirty flags.  It can only be restored to its
originating console with identical dimensions.  Font registrations are
instance resources and are not copied.

For libretro, `st_console_display_libretro_frame_size()` queries the physical
display's last completed frame and `st_console_display_libretro_frame_copy()`
copies it.  The size can change between those calls, including on console
activation.  Copy therefore takes both the destination stride and its row
capacity; an undersized destination is rejected without writing to it.

== Input Events

Each logical console has one ordered event queue.  Translated keys, physical keys,
committed text, DoorWay scan codes, mouse actions, resize, focus, and close are
distinct event types.  Backends post only semantics they actually receive.

`st_console_display_post_event()` delivers host input to the console active
when delivery is serialized.  `st_console_post_event()` explicitly targets the
given console's queue, including an inactive console.  Switching does not move
already queued events between consoles.

Normalized non-text keys use `ST_CONSOLE_KEY_*`; ASCII controls retain their
byte values.  Graphical backends translate Control combined with an ASCII
letter, `@`, `[`, `\\`, `]`, `^`, `_`, or Space into that control's
`KEY_CODE` byte.  Physical events carry evdev-style identity, modifiers,
press/release, and repeat state.  Held physical-key state belongs to the
display, including physical events submitted through the explicit-console
entry point.  Focus loss queues releases on the event's target console before
the focus event and clears the display's held set.  Clearing queued events does
not alter held state.
`st_console_synthesize_physical_key()` atomically compares that held state and
queues only a real transition, so a failed queue reservation cannot change the
state without delivering its edge.

X11 committed text comes from its UTF-8 input context, preserving layouts,
dead keys, compose processing, and external input methods.  Wayland uses
xkbcommon.  SDL and Windows also separate physical identity from committed
Unicode.  ANSI and ncurses decode only what the enclosing terminal supplies;
they do not invent physical identities or key-release events.

ANSI and ncurses host-terminal resizing schedules an independent repaint of
the retained screen, even while the application is idle.  A resize event
reports the new host dimensions; it does not resize the logical console.

Mouse coordinates are in the logical console pixel grid, independent of final
window scaling.  Button state, event-time modifiers, action, coordinates, and
wheel deltas remain separate fields.

== Window and Host Operations

Bitmap window backends consume Alt+Left and Alt+Right to snap to adjacent
integer display scales, Alt+Home to centre the window where positioning is
permitted, and Alt+Enter to toggle fullscreen.  The monitor containing the
window—not the whole multi-monitor root desktop—controls centring, limits,
maximization, and fullscreen.  Wayland also consumes Alt+left-drag for
interactive movement.  These commands are not also delivered as application
keys.

Title and pointer visibility are retained per console and restored on
activation.  Clipboard, URL, and fullscreen operations belong to the physical
display; the single-console convenience calls forward to that display.  Each
operation independently returns `IO_ERROR_NOT_SUPPORTED` when unavailable.
Backend-returned text is released with
`st_console_free_text()` so allocation does not cross the library boundary.

`st_console_display_get_scaling()` reports the active bitmap window's physical
scale relative to its source raster while accounting for aspect correction.
The X11, Wayland, SDL, GDI, and Quartz backends support the query.  Text,
libretro, and headless backends return `IO_ERROR_NOT_SUPPORTED`.  A window
smaller than the
minimum source presentation is an invalid backend state and returns
`IO_ERROR_OUT_OF_RANGE`; the result argument is unchanged on every failure.

Unresolved host capability detection is documented in
`console/CAPABILITY_GAPS.md`.  Missing implementation work is not a
host-capability gap.
