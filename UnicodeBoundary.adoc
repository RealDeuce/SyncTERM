= Terminal Wire and Unicode Boundary
:toc:

== Status and Scope

This is the design contract for the connected-session input and output
boundary.  It applies to the future ports of `term.c`, CTerm, and the connected
Wren bindings.  It does not describe those ports as already implemented.

Exact C and Wren function names may be chosen during implementation.  The
separation between default Unicode text operations and explicitly raw byte
operations is normative.

The design must support all of the following at the same time:

* Remote text may use UTF-8 or a configured legacy single-byte encoding.
* A UTF-8 scalar may be split across any number of connection reads or CTerm
  writes.
* Wren scripts which operate on text must see the same Unicode regardless of
  the remote encoding.
* Terminal controls and binary protocol payloads must retain their exact wire
  bytes.
* Scripts which intentionally inspect or modify the wire stream must have an
  explicit raw-byte interface.
* CTerm and Wren must not decode the same filtered stream independently.

== Core Rule

There are two representations but only one wire-to-Unicode translation:

[source,text]
----
wire bytes
    |
    +-- explicit raw hooks and transfer detection
    |
    `-- CTerm protocol classification
            |
            +-- controls and binary payloads --> byte parser
            |
            `-- graphic byte spans
                    |
                    `-- one streaming decoder
                            |
                            +-- Unicode Wren hooks and matchers
                            `-- CTerm text rendering
----

The Unicode consumers share the output of one decoder.  Giving Wren and CTerm
separate decoders would allow their state, invalid-input recovery, and response
to hook replacements to diverge.

== Receive Path

The receive path processes data in this order:

. The connection produces ordered raw bytes.
. Explicit raw Wren hooks may inspect, drop, or replace those bytes.  Transfer
  and auxiliary-protocol detection also operates on the raw stream at its
  defined point in this stage.
. CTerm classifies the resulting bytes according to its current parser and
  emulation state.
. CTerm consumes control sequences and exact-byte payloads without translating
  them.
. CTerm submits only graphic byte spans to the session's streaming decoder.
. Default Wren input and matching hooks receive decoded Unicode.
. Text which remains after the Unicode hooks is rendered by CTerm without
  being encoded and decoded again.

CTerm must participate in classification because only its parser state can
distinguish printable text from such inputs as PETSCII and ATASCII controls,
DoorWay literals, VT52 and BBC trailing parameters, sixel and macro strings,
and downloaded-font payloads.  A whole-stream conversion in `term.c` would
corrupt some of those inputs.

Translation policy may be owned by the connected-session code in `term.c`, but
the CTerm boundary must let the parser invoke that policy only for classified
graphic data.  The implementation may use a callback or typed parser events;
it must not duplicate the terminal parser in `term.c` merely to locate text.

== Decoder State

The decoder is session state, not call-local state.  In UTF-8 mode it retains
an incomplete prefix across connection reads and CTerm writes.  It is not
finished or flushed at an ordinary buffer boundary.

The decoder must define and test these transitions:

* completion of two-, three-, and four-byte scalars across every split point;
* an invalid continuation followed by a byte which must be reconsidered;
* a terminal control interrupting an incomplete UTF-8 sequence;
* an encoding change, terminal reset, disconnect, or end of input while a
  prefix remains incomplete; and
* reset after a decode error without losing the following valid input.

Malformed-input policy must be applied once by the shared decoder so Wren and
the display observe the same result.  The exact replacement or notification
policy remains an implementation decision.  Basic incremental decoding must
not perform NFC normalization or grapheme buffering implicitly; those are
separate text-presentation policies.

== Wren Boundary

Wren `String` values are UTF-8 text by default at the connected-session API.
Their ability to expose and contain bytes does not make the default terminal
hooks wire-encoding-dependent.

The binding shall expose these semantic categories; final names may refine the
examples:

[cols="2,3",options="header"]
|===
| Category | Contract

| Default input hook, such as `Hook.onInput`
| Receives a Unicode scalar or UTF-8 text unit independent of whether the
  remote sent UTF-8, CP437, or another configured codepage.  Unicode
  replacement text remains in the semantic text path.

| Default streaming matcher, such as `Hook.onMatch`
| Matches the decoded UTF-8 stream.  A Wren pattern containing non-ASCII text
  therefore has the same meaning for every supported wire encoding.

| Explicit raw hook, such as `Hook.onWire`
| Receives exact wire bytes before Unicode decoding.  Raw replacements remain
  bytes and re-enter protocol classification.

| Text send, such as `Conn.send`
| Accepts Unicode text and encodes it using the active outgoing wire encoding
  before the transport performs protocol framing such as Telnet IAC escaping.

| Explicit raw send, such as `Conn.sendRaw`
| Sends caller-supplied bytes without character encoding.  Transport-level
  behavior specified by the connection still applies unless the particular
  raw operation explicitly bypasses it.

| Raw connection inspection
| Peek and receive operations intended to expose transport buffers are named
  and documented as raw.  They do not masquerade as decoded text.

| Direct terminal text, such as `CTerm.write`
| Accepts UTF-8 semantic terminal input.  It does not depend on the remote
  wire encoding.
|===

Existing ASCII-oriented scripts remain source-compatible because ASCII byte
values and Unicode scalar values coincide.  A script which deliberately
depends on a non-ASCII wire byte or a binary protocol must use the explicit
raw API.  The connected Wren port must inventory current hooks before settling
names and migration aliases.

Hook return contracts remain synchronous.  A Unicode replacement is delivered
directly to CTerm's semantic text path; it is not round-tripped through the
legacy encoder.  A raw replacement is processed as bytes and may consequently
affect terminal controls, transfer detection, or binary payloads according to
where the raw hook is placed.

== Send Path

Outgoing data also has separate text and raw lanes:

[source,text]
----
Wren text, clipboard text, and text-key events
        |
        `-- one Unicode-to-wire encoder --> connection framing --> wire

CTerm protocol responses and explicit raw operations
        |
        `--------------------------------> connection framing --> wire
----

CTerm responses which mix protocol framing with screen text, such as selected
area transmission, must preserve the distinction internally.  CTerm may emit
typed raw and text spans, or use separate callbacks.  `term.c` encodes only the
text spans.  It must never character-encode escape introducers, binary fields,
or other protocol bytes.

The outgoing encoder needs an explicit policy for Unicode scalars which the
selected legacy codepage cannot represent.  That policy must not affect raw
responses.  Partial-send accounting is measured in final wire bytes, after
text encoding and connection framing.

== Ownership

[cols="2,3",options="header"]
|===
| Owner | Responsibility

| Connection
| Ordered byte transport, transport framing, queueing, and raw send/receive.

| `term.c` connected session
| Active incoming and outgoing encoding policy, Wren VM and hook dispatch,
  transfer detection, and coordination of the raw and text lanes.

| CTerm
| Terminal and emulation parser state; classification of control, binary, and
  graphic input; terminal mode changes; rendering and protocol responses.

| Streaming decoder/encoder
| Stateful conversion and its invalid or unmappable input policy.  A decoder
  instance belongs to one ordered input stream.

| Console
| Storage and presentation of resolved cells and pixels.  It is not the owner
  of wire encoding or terminal protocol parsing.
|===

== Required Verification

The port is not complete until focused tests cover at least:

* the same non-ASCII Wren match and rendered glyph from equivalent UTF-8 and
  legacy-codepage sessions;
* every split point of valid multi-byte UTF-8 scalars;
* malformed and incomplete UTF-8 followed by valid input;
* raw-hook drop and replacement before decoding;
* Unicode-hook drop and replacement without an encode/decode round trip;
* PETSCII and ATASCII controls which share the byte space with graphic data;
* exact preservation of downloaded fonts and other binary payloads;
* codepage and terminal-mode changes while text is streaming;
* Unicode-to-legacy output, including the chosen unmappable-scalar policy;
* raw CTerm responses which contain bytes invalid in the selected text
  encoding; and
* mixed raw/text responses such as selected-area transmission.

== Decisions Deferred to the Port

The architecture does not yet choose:

* final Wren method names and compatibility aliases;
* whether default input hooks fire per scalar or per grapheme;
* the malformed-input replacement and notification policy;
* the outgoing unmappable-scalar policy; or
* the concrete C callback or typed-event interface between `term.c` and CTerm.

Those choices must preserve the central invariant: one ordered raw stream, one
parser-aware text classification point, and one shared Unicode conversion for
all semantic text consumers.
